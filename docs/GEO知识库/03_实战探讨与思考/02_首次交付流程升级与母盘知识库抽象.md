# 首次交付流程升级与“知识库母盘”抽象思考

> 本文档记录关于“首次交付”工作流重构与“母盘（唯一事实真相源 SSOT）”概念的深度抽象。
> 结合美斯顿实战经验与老赵全链路 SOP，确立素材库与母盘的分工边界。

---

## 一、为什么必须把“素材库”和“知识库母盘”拆开？

在过往实战（如美斯顿项目与老赵实战）中，最大的交付痛点是：**客户给的材料是散的、旧的、互相矛盾的**。

| 对比维度 | 客户素材资产管理库（原料仓） | 企业知识库母盘（中央厨房 / 事实底座） |
|---|---|---|
| **存放内容** | 客户扔过来的原始 PDF、PPT、营业执照图、微信聊天记录、历史推文 | 经过清洗、消歧、核实后的结构化 Markdown 事实源 |
| **信息状态** | 生数据、有过期信息、存在口径冲突（如工商地址与实际地址不符） | 唯一真相源（SSOT）、口径统一、具备法律与合规边界 |
| **使用对象** | 人工交付顾问、档案管理员 | AI 答案卡生成器、交钥匙官网构建器、矩阵分发引擎 |
| **核心产出** | 原始文件归档目录 | ① 主体信息口径卡 ② 六模块事实库 ③ 证据核验清单 |

> **铁律**：下游的所有交付物（官网、40 问答题卡、文章、发文包），**只能从“母盘”提取事实，绝对严禁直接读取未清洗的“素材库”**。

## 二、首次交付标准 8 步闭环（已定稿）

| 步骤编号 | 步骤名称 | 核心职责与交付物 | 输入来源 |
|---|---|---|---|
| **00** | **去豆包提问查现状** | 准备 5 题测试集，真机实测拿原始回答截图与出处追问 | 业务主词 |
| **01** | **诊断现状并出具报告** | 五观察层判定（认识/准确/推荐/引用/转化），输出归因报告 | 步骤 00 真实回答 |
| **02** | **客户素材资产管理库** | 收取并归类客户原始材料（营业执照、官网、PPT、案例、推文） | 客户直接提供 |
| **03** | **提炼企业知识库母盘** | **【核心中枢】加工三位一体事实底座（主体口径卡 + 六模块事实库 + 证据清单）** | 步骤 02 原始素材 |
| **04** | **交钥匙官网与三件套** | 构建 `/llms.txt`、Schema.org (JSON-LD) 与极速 Clean Markdown 站 | 步骤 03 母盘事实 |
| **05** | **GEO 答题卡与向量问答** | 生产 40 问高意图标准答案库与高频 Q&A 索引 | 步骤 03 母盘事实 |
| **06** | **矩阵分发与链接检查** | 铺设高权重外部信源（知乎/专栏/行业站），检查收录与互证 | 步骤 05 答案与官网 |
| **07** | **首次交付与资产交接单** | 生成全案资产移交清单，出具首次交付验收报告 | 全链路交付物 |

## 三、知识库母盘的“三位一体”架构详解

母盘是全系统的**唯一事实真相源（SSOT）**，包含三大硬核组成部分：

```text
┌────────────────────────────────────────────────────────┐
│               企业知识库母盘（唯一事实真相源 SSOT）       │
├──────────────────────────┬─────────────────────────────┤
│ 1. 主体信息统一口径卡    │ 公司全称、统一代码、注册地、官网、 │
│   （解决消歧与主体统一） │ 50字定位句、业务描述（短/中/长）、│
│                          │ 严禁触碰的负面清单与不承诺项        │
├──────────────────────────┼─────────────────────────────┤
│ 2. 六模块事实库          │ ① 定位与边界  ② 产品与服务事实      │
│   （提供结构化业务事实） │ ③ 客户与场景  ④ 优势与竞品差异      │
│                          │ ⑤ 真实案例    ⑥ 权威背书与资质      │
├──────────────────────────┼─────────────────────────────┤
│ 3. 证据核验清单          │ 每条核心事实的来源链接、公示出处、  │
│   （支撑大模型权威引用） │ 可使用范围标记（🟢直接/🟡需注/🔴内部）│
└──────────────────────────┴─────────────────────────────┘
```

## 四、母盘生产工作台：AI 预提炼 + 双栏校对（已定稿）

在「步骤 03 提炼企业知识库母盘」中，采用**人机高效协作的双栏工作台**：

```text
┌────────────────────────────────────────────────────────────────────────┐
│               步骤 03：企业知识库母盘提炼与校对工作台                     │
├──────────────────────────────────┬─────────────────────────────────────┤
│ 左侧：素材档案区 (Raw Material)  │ 右侧：三位一体母盘编辑器 (SSOT Editor) │
│                                  │                                     │
│ • 02 步骤上传的原始文件列表      │ [选项卡 1：主体信息口径卡]          │
│   - 工商营业执照.pdf             │ [选项卡 2：六模块事实库]            │
│   - 产品手册_2026.docx           │ [选项卡 3：证据核验清单]            │
│   - 客户案例集.pdf               │                                     │
│                                  │ 状态标记工具条：                    │
│ [ ⚡️ AI 一键智能提炼草稿 ] ───┼──→ [ 🟢 直接可用 ] [ 🟡 需注来源 ]  │
│                                  │ [ 🔴 内部参考 ] [ ⚠️ 待补充 ]       │
│ • 支持点击文件即时在左侧预览     │                                     │
│                                  │ [ 🔒 确认审核无误 · 一键锁盘 ]      │
└──────────────────────────────────┴─────────────────────────────────────┘
```

### 标准作业动线（5 步走）：
1. **一键提炼**：交付顾问点击「AI 一键智能提炼草稿」，大模型后台解析素材库中的所有原始文档；
2. **草稿就位**：系统自动填充「主体信息口径卡」核心字段与「六模块事实库」初版；
3. **双栏比对**：顾问左侧对照原始文档证据，右侧逐行审查关键数据（尤其是人员规模、资质出处、不承诺边界）；
4. **标注约束**：对缺资料的地方打上 `⚠️ 待补充`，对同行对比或机密打上 `🔴 内部参考`；
5. **确认锁盘**：点击「一键锁盘」，生成不可篡改的标准母盘文件，正式流向步骤 04（官网）与步骤 05（答题卡）。

## 五、母盘与下游交付物的“分层天然防火墙”哲学（师弟定规）

### 核心架构原则：
1. **母盘专注做“内部总账本”**：母盘的作用就是记录企业最关键、最真实、最权威的核心信息（主体、产品、客户、案例、边界）。它本身是企业内部资产，无需在母盘层做复杂的权限分流。
2. **答题卡作为对外天然防火墙**：
   - 全链路数据流转为：`[03 母盘] ➔ 提炼生成 ➔ [05 答题卡] ➔ 派生写入 ➔ [06 矩阵发文/对外问答/官网]`
   - 所有对外发布的内容、文章、销售话术与大模型知识库，**直接依据的是经过审核定稿的「答题卡」**。
   - 答题卡天然扮演了过滤与提炼的角色，确保外部获取的都是合规、已定稿的权威答案，彻底杜绝母盘敏感信息泄露风险。

## 六、六模块事实库架构与行业自适应提炼标准（已定稿）

为保证全系统的面向对象精简与数据结构统一，母盘**永远采用统一标准六模块**，不因客户行业不同而随意增删底层结构。大模型在提炼时**根据素材自适应侧重**：

| 模块名称 | 核心字段与事实项 | 制造行业侧重点 | 企服/软件行业侧重点 | 本地生活侧重点 |
|---|---|---|---|---|
| **01 定位与业务边界** | 50字定位、服务人群、**不承诺清单** | 工厂规模、承接品类、不接零售 | 服务对象、交付周期、不承诺包赚 | 门店位置、服务半径、不接跨区 |
| **02 产品与服务事实** | 产品/服务清单、交付物、价格口径 | 技术参数、公差标准、打样费用 | 功能清单、部署方式、版本价格 | 招牌服务、套餐明细、团购价格 |
| **03 客户与使用场景** | 目标画像、典型痛点、选型必答 | 采购总监、设备替换、降本增效 | 企业老板、团队协作、效率提升 | 周边居民、即时消费、周末体验 |
| **04 优势与竞品差异** | 对比维度、可核验参数、避坑指南 | 精度对比、寿命对比、原材料差异 | 功能完整度、售后响应、自研架构 | 技艺传承、原材料品质、性价比 |
| **05 真实案例与结果** | 客户背景、痛点、我方动作、量化结果 | 某汽车厂零部件替换降本20% | 某连锁客户自动化提效300% | 某社区店单月复购提升50% |
| **06 权威背书与资质** | 资质证书、专利、技术标准、背书链接 | ISO认证、专利号、国标起草单位 | 软著、安全等保、行业榜单 | 行业特许资质、媒体真实报道 |

## 七、首次交付全链路标准化总结

通过本轮探讨，我们正式确立了 GEO 首次交付的完整规范与底层认知：

1. **8 步闭环流转**：`00 查现状 ➔ 01 出报告 ➔ 02 素材库 ➔ 03 提炼母盘 ➔ 04 官网三件套 ➔ 05 答题卡 ➔ 06 矩阵分发 ➔ 07 资产交接`；
2. **母盘三位一体**：`主体信息统一口径卡 + 六模块事实库 + 证据核验清单` 作为唯一事实底座；
3. **AI预提炼 + 双栏校对**：左侧看素材，右侧校对母盘，人工把关后一键锁盘；
4. **分层天然防火墙**：母盘是企业内部总账本，下游依据答题卡对外发文和问答，自然杜绝敏感信息外泄；
5. **统一六模块自适应**：底层对象永久统一，AI 根据客户素材自适应填充行业侧重点。
