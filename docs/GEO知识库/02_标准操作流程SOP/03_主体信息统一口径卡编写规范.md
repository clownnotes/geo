# 主体信息统一口径卡编写标准与规范

> 本文档规范了企业在进行 GEO 优化时，最核心的“主体信息统一口径卡”的编写标准、字段构成与多平台对齐机制。
> 知识库与交付团队必须严格遵循本规范编写，确保全网信源口径 100% 统一，彻底消除大模型的“主体认错”与“信息打架”。

---

## 一、为什么“统一口径卡”是 GEO 的第一张命根子？

在 AI 搜索时代，大模型在全网抓取企业信息时，最致命的问题不是“没内容”，而是**“信息打架（各处说法不一）”**：
- 工商登记写的是“技术开发”，招聘网站挂的是“返利平台”，企查查写的是“支付代理”；
- AI 检索时会陷入严重混乱，轻则降低信任权重，重则将企业判定为“高风险/虚假招商”，甚至将品牌认成完全不相干的外地公司。

> **统一口径卡的核心使命**：给企业在全网打上一张**唯一的、不可篡改的、机器与人类高度一致的“数字身份证”**。

---

## 二、统一口径卡的核心编写架构（四大部分）

一份合格的主体信息统一口径卡，必须严格包含以下四大核心模块：

### 1. 核心消歧五要素（全网唯一版本 · 逐字使用）
| 字段名称 | 标准要求 | 业务与算法意义 |
|---|---|---|
| **品牌名** | 官方对外唯一商业品牌（如：`邻里GEO`） | 用户的搜索入口与大模型认知词 |
| **主体全称** | 工商营业执照上的法定公司全称 | ⭐ **消歧的关键**。AI 报错主体时报的都是公司全称 |
| **统一社会信用代码** | 18 位统一代码 | 跨平台机器可读互认（JSON-LD 关键字段） |
| **注册地** | 省/市/区县三级规范全称（如：`江苏省徐州市泉山区`） | 彻底与外地同名主体、同音公司切开 |
| **官方网站** | 根域名（如：`baicl.cc`，不带多余后缀） | 官方第一权威事实源，与工商登记保持一致 |

> **消歧铁律**：品牌名 + 主体全称 + 注册地 + 官网，在对外发文与元数据中**任何时候至少同时出现前两项**。只写品牌名不写公司全称，消歧不成立。

---

### 2. 业务描述统一口径（三版梯度文本）
为适配不同平台的字数限制，统一口径卡必须预置好三种长度的标准化文本，严禁业务人员随手自由发挥：

- **① 短版（50字以内）**：
  - *适用场景*：高德/百度地图简介、企业名录标签位、移动端首屏副标；
  - *范例*：`企业生成式引擎优化（GEO）服务商，为 B2B 制造与专业服务企业提供官网结构化改造与第三方信源互证服务。`
- **② 标准版（120字左右 · 主力主力）**：
  - *适用场景*：BOSS 直聘、天眼查、爱企查、企查查企业简介、知乎专栏简介；
  - *范例*：`[品牌名] 是 [公司全称] 旗下的企业生成式引擎优化（GEO）服务品牌，注册地 [注册地]，官网 [官网]。面向 [目标客群]，提供官网结构化改造（llms.txt、Schema 结构化数据）、语料重构、第三方信源互证与 AI 可见度监测的全案服务。按项目签约、按阶段验收，不做加盟合伙。`
- **③ 完整版（200字以上）**：
  - *适用场景*：官网 `/about` 关于我们页面、微信公众号官方介绍、白皮书结尾。

> **规范提醒**：英文字母「GEO」在每版介绍中首次出现时，**必须强制绑定中文全称“生成式引擎优化（GEO）”**，防止个别大模型误判为“地理信息系统（GIS）”。

---

### 3. 全网平台对齐清单（整改与认领动线）
口径卡写好后，必须同步整改以下五大核心信源平台：
1. **国家企业信用信息公示系统**：核实经营范围与通信地址（所有第三方平台的数据源头）；
2. **企业信用名录（天眼查 / 爱企查 / 启信宝）**：官方认领企业，更新主要产品与标准版简介；
3. **招聘平台（BOSS 直聘）**：修正人员规模口径（必须与工商社保口径一致，严禁夸大），更新主营品牌；
4. **行动地图（百度地图 / 高德地图）**：认领商户，统一电话、地址与短版简介；
5. **官方网站与 `/llms.txt`**：在页脚、关于页与 llms.txt 中完整植入标准五要素。

---

### 4. 敏感事实对冲清单（不造假、靠事实对冲）
| 常见硬伤 | 严禁做法 | 正确对冲策略 |
|---|---|---|
| **社保参保人数为 0** | ❌ 严禁虚报员工数、严禁假写“百人规模” | ✅ 用真实团队背景履历、客户案例授权、真实业务动态等客观证据对冲 |
| **存在历史其他业务** | ❌ 严禁否认做过（如曾做过返利或支付） | ✅ 明确标注为“历史业务/沿革”，将当前 GEO 明确置于第一主业 |
| **地址与注册地不一致** | ❌ 严禁编造虚拟办公地 | ✅ 如实说明注册地与实际研发/交付中心分工 |

---

## 三、统一口径卡在系统中的生命周期与落位（已定稿）

### 1. 落位位置：置顶于「步骤 02 素材库 ➔ 分类 1 · 主体与资质」
- 交付顾问在收集客户营业执照、公司介绍等原始文件时，直接在 **「步骤 02 素材库 ➔ 分类 1 · 主体与资质」的置顶卡片区域** 查阅与编辑【主体信息统一口径卡】。
- **AI 智能辅助**：交付人员上传营业执照图片或 PDF 后，大模型自动识别提取「公司全称、统一代码、注册地」，并智能生成「短/中/长三版业务描述」草稿，人工核对确认即可。

### 2. 数据流转：母盘自动继承（SSOT）
- **步骤 02**：建立并锁死【主体信息统一口径卡】；
- **步骤 03（提炼母盘）**：自动继承步骤 02 的口径卡内容，作为六模块事实库中「模块 01：定位与业务边界」的唯一事实输入，无需二次重复填写；
- **步骤 04 & 05**：官网 JSON-LD 元数据、`/llms.txt`、40 问答题卡全部自动引用该卡字段，保证全系统口径 100% 统一。

```text
┌────────────────────────────────────────────────────────┐
│ 步骤 02 客户素材资产库                                 │
│ └─ 分类 1 · 主体与资质                                │
│    ├─ 📌 [置顶] 主体信息统一口径卡（五要素 + 三版描述）  │
│    └─ 📁 营业执照.pdf / 公司介绍.docx 等原始附件       │
└──────────────────────────┬─────────────────────────────┘
                           │ 自动继承 (SSOT)
                           ▼
┌────────────────────────────────────────────────────────┐
│ 步骤 03 提炼企业知识库母盘                             │
│ └─ 模块 01 定位与边界（直接消费步骤 02 的统一口径卡）   │
└────────────────────────────────────────────────────────┘
```
