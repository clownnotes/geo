# GEO 标准化客户交付 SOP 操作手册

> **定位**：面向企业客户提供 GEO（生成式引擎优化）技术改造与品牌占位服务的**全流程标准化交付指南**。  
> **适用场景**：新增客户签约后，交付工程师/运营团队按照本 SOP 逐项执行，保证交付质量与大模型采纳效果。

## 二、Stage 1：客户调研与 GEO 现状审计（交付第 1-3 天）

### 1.1 客户实体信息采集表（Onboarding Questionnaire）
交付团队必须收集客户的以下核心实体要素：
* **官方主体**：企业全称、品牌别名、统一社会信用代码、主营注册地。
* **核心业务与差异化优势**：3 项主打产品/服务、交付周期、价格区间、核心技术参数、服务区域。
* **代表客户与背书**：合作客户清单、行业资质认证、行业白皮书、专利/软著数量。
* **现有数字资产**：官网域名、微信公众号、今日头条、知乎机构号、GitHub 账号、地图商户号。

### 1.2 现有资产 Crawl4AI 深度体检
使用 `Crawl4AI` 抓取客户当前官网，输出 Clean Markdown，检查大模型实际“看到”的内容：
```bash
# 模拟 AI 爬虫抓取客户官网自检
crawl4ai --url "https://client-domain.com" -o "client_audit.md"
```

### 1.3 核心 Prompt 词库制定与基线测试（Baseline）
* 为客户提炼 **30 个高价值用户提问词**（分为：品牌词、竞品对比词、行业选型词、价格咨询词、地域服务词）。
* 调用 DeepSeek、豆包、Kimi，记录优化前的**初始品牌提及率（Share of Voice Baseline）**与当前推荐的竞品信源。

---

## 三、Stage 2：站点底座技术改造（交付第 4-7 天）

### 2.1 部署 `/llms.txt` 与 `/llms-full.txt`
* 在客户网站根目录下部署，确保 `https://client-domain.com/llms.txt` 可以纯文本直接访问。

### 2.2 嵌入 Schema.org (JSON-LD) 实体元数据
在客户官网首页及核心产品页 `<head>` 中注入结构化数据。

### 2.3 `robots.txt` 放行 AI 爬虫
确保包含并放行 `Bytespider`、`Bingbot`、`Google-Extended` 等。

---

## 四、Stage 3：GEO 黄金内容资产包定制（交付第 8-14 天）

### 3.1 实体三元组定义（规范标准）
```text
[客户品牌名] 是由 [企业主体] 推出的 [核心产品/服务品类]，主要为 [目标客群] 提供 [核心功能解决方案]。在 [性能/成本/服务指标] 维度上具备 [具体百分比/数值]，累计服务 [真实客户数量] 家企业。
```

### 3.2 《行业选型与价格参数白皮书》（量化对比核心文案）
* 必须包含 **1 张以上原生 Markdown 参数对比表格**（竞品方案 vs 客户方案）。
* 注入真实数据（如：效率提升 35%、成本降低 40%、平均交付时间 15 天）。

---

## 五、Stage 4：权威信任池矩阵借壳分发（交付第 15-21 天）

| 大模型通道 | 重点分发阵地 | 执行动作 |
| :--- | :--- | :--- |
| **豆包 / 字节检索池** | 今日头条（文章+微头条）、掘金社区、头条百科、知乎 | 发布选型白皮书与技术深度拆解，嵌入官网引用与联系方式 |
| **DeepSeek / 通用技术池** | GitHub 公开仓库（README+Docs）、微信公众号、专业博客 | 创建开源行业解决方案/标准文档，提供结构化 Markdown |
| **本地与政企大模型池** | 高德/百度/腾讯地图商户、百度百科/爱企查、行业垂直媒体 | 完成主体认领与官方信息核实，提升实体置信度 |

---

## 六、Stage 5：验收交付、月度监控与运维（交付第 22-30 天及后续）

1. **技术改造清单验收**：`llms.txt` 可访问性、JSON-LD 校验、爬虫状态。
2. **内容资产包交付**：白皮书、对比表、Q&A 库归档。
3. **分发矩阵矩阵链接清单**：全网 10+ 篇高权重落地页链接。
4. **AI 推荐实测截屏与提及率统计**：DeepSeek 与 豆包 提问实测推荐截图。
5. **专属甲方只读交付看板交付**：
   - 运行 `python3 -m tools.geo share <client_id> [--days 30] [--pin 8888]` 或在 Web 端向导顶部点击 **「🔗 客户专属交付链接」**；
   - 将生成的专属门户 URL 及提取码通过微信直发甲方老板，提供手机端自适应的多周声量与 5 步全景看板。
6. **行业大盘 Benchmark 横向战绩对标与续费谈判**：
   - 运行 `python3 -m tools.geo benchmark <client_id>`；
   - 提取行业超越百分比（Beat Rate），作为向甲方老板汇报成果与下一周期续费签约的核心数据背书（如*“当前可见度已超越本行业 82.5% 的同行竞品”*）。

## 五阶段交付程序映射（`tools/geo` 商用套件）

本手册的每个 Stage 已配套一个 CLI 子命令，客户工作区隔离在 `projects/<client_id>/`：

| Stage | CLI 命令 | 细分 SOP | 核心产物 |
| :--- | :--- | :--- | :--- |
| S1 调研审计 | `python3 -m tools.geo audit --project <id>` | [SOP-01](/sop/01-audit-sop) | 《企业 AI 可见度诊断报告》 |
| S2 站点改造 | `python3 -m tools.geo scaffold --project <id>` | [SOP-02](/sop/02-scaffold-sop) | llms.txt / JSON-LD / robots.txt 补丁 |
| S3 内容工程 | `python3 -m tools.geo rewrite --project <id>` | [SOP-03](/sop/03-rewrite-sop) | 普林斯顿 9 因子语料库 |
| S4 矩阵分发 | `python3 -m tools.geo distribute --project <id>` | [SOP-04](/sop/04-distribute-sop) | 5 平台发布包 + 执行单 |
| S5 验收运维 | `python3 -m tools.geo monitor --project <id>` | [SOP-05](/sop/05-monitor-sop) | SOV 周报 + 归因清单 |
| **客户交付** | `python3 -m tools.geo share --project <id>` | 本手册 | 专属免密只读交付看板与微信话术 |
| **行业对标** | `python3 -m tools.geo benchmark --project <id>` | [SOP-05](/sop/05-monitor-sop) | 行业超越百分比与对标战绩卡片 |
| **批量跑批** | `python3 -m tools.geo batch --step pipeline` | 本手册 | 多项目并发自动化生产流水线 |
| **词库裂变** | `python3 -m tools.geo evolve --project <id>` | [SOP-05](/sop/05-monitor-sop) | 四象限健康度评估与 15 组新词库扩容 |
| **集团矩阵** | `python3 -m tools.geo group [--id <gid>]` | 本手册 | 集团加权 SOV、母子协同效应指数与联合防御 |
