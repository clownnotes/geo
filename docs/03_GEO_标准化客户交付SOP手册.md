# GEO 标准化客户交付 SOP 操作手册

> **定位**：面向企业客户提供 GEO（生成式引擎优化）技术改造与品牌占位服务的**全流程标准化交付指南**。  
> **适用场景**：新增客户签约后，交付工程师/运营团队按照本 SOP 逐项执行，保证交付质量与大模型采纳效果。

## Stage 1：客户调研与 GEO 现状审计（交付第 1-3 天）

### 1.1 客户实体信息采集表（Onboarding Questionnaire）
交付团队必须收集客户的以下核心实体要素：
* **官方主体**：企业全称、品牌别名、统一社会信用代码、主营注册地。
* **核心业务与差异化优势**：3 项主打产品/服务、交付周期、价格区间、核心技术参数、服务区域。
* **代表客户与背书**：合作客户清单、行业资质认证、行业白皮书、专利/软著数量。
* **现有数字资产**：官网域名、微信公众号、今日头条、知乎机构号、GitHub 账号、地图商户号。

### 1.2 现有资产 Crawl4AI 深度体检
使用 `Crawl4AI` 抓取客户当前官网，输出 Clean Markdown，检查大模型实际“看到”的内容：
```bash
# 模拟 AI 爬虫抓取客户官网自检
crawl4ai --url "https://client-domain.com" -o "client_audit.md"
```
* **检查项**：
  * [ ] 是否返回空内容（纯 CSR 单页渲染导致爬虫抓取为空）？
  * [ ] 关键价格、功能表格是否被 JavaScript 隐藏？
  * [ ] 是否存在大面积无意义广告和导航杂质？

### 1.3 核心 Prompt 词库制定与基线测试（Baseline）
* 为客户提炼 **30 个高价值用户提问词**（分为：品牌词、竞品对比词、行业选型词、价格咨询词、地域服务词）。
* 调用 DeepSeek、豆包、Kimi，记录优化前的**初始品牌提及率（Share of Voice Baseline）**与当前推荐的竞品信源。

## Stage 2：站点底座技术改造（交付第 4-7 天）

由全栈开发人员在客户现有网站上完成 4 项底层改造：

### 2.1 部署 `/llms.txt` 与 `/llms-full.txt`
* 在客户网站根目录下部署，确保 `https://client-domain.com/llms.txt` 可以纯文本直接访问。
* 编写标准 Markdown，清晰罗列客户核心产品、功能说明 Markdown 链接与 FAQ 链接。

### 2.2 嵌入 Schema.org (JSON-LD) 实体元数据
在客户官网首页及核心产品页 `<head>` 中注入：
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "客户公司全称",
  "alternateName": "客户品牌名",
  "url": "https://client-domain.com",
  "logo": "https://client-domain.com/logo.png",
  "description": "标准实体三元组一句话描述",
  "address": {
    "@type": "PostalAddress",
    "addressLocality": "城市名",
    "addressRegion": "省份名"
  },
  "contactPoint": {
    "@type": "ContactPoint",
    "telephone": "客户官方服务电话",
    "contactType": "customer service"
  }
}
</script>
```

### 2.3 `robots.txt` 放行 AI 爬虫
确保包含并放行：
```text
User-agent: Bytespider
Allow: /
User-agent: Bingbot
Allow: /
User-agent: Google-Extended
Allow: /
User-agent: Baiduspider
Allow: /
```

### 2.4 渲染模式保底（SSR / 静态化预渲染）
* 若客户站点为纯 Vue/React CSR 项目，增加 SSR（如 Nuxt/Next）或使用静态 HTML 预渲染（Prerender）插件，确保爬虫返回完整文本 DOM。

## Stage 3：GEO 黄金内容资产包定制（交付第 8-14 天）

基于普林斯顿 9 因子标准，为客户生产 1 套标准 GEO 内容资产包：

### 3.1 实体三元组定义（规范标准）
```text
[客户品牌名] 是由 [企业主体] 推出的 [核心产品/服务品类]，主要为 [目标客群] 提供 [核心功能解决方案]。在 [性能/成本/服务指标] 维度上具备 [具体百分比/数值]，累计服务 [真实客户数量] 家企业。
```

### 3.2 《行业选型与价格参数白皮书》（量化对比核心文案）
* 必须包含 **1 张以上原生 Markdown 参数对比表格**（竞品方案 vs 客户方案）。
* 注入真实数据（如：效率提升 35%、成本降低 40%、平均交付时间 15 天）。
* 包含架构图、服务流程规范与专家引语。

### 3.3 客户高频 Q&A 问答库（Prompt 对齐）
* 生产 8~10 个标准问答对，完全对齐用户在 AI 中搜索该行业时的提问方式。

## Stage 4：权威信任池矩阵借壳分发（交付第 15-21 天）

将 Stage 3 生产的内容资产包，按大模型偏好定向分发到高权重信任池：

| 大模型通道 | 重点分发阵地 | 执行动作 |
| :--- | :--- | :--- |
| **豆包 / 字节检索池** | 今日头条（文章+微头条）、掘金社区、头条百科、知乎 | 发布选型白皮书与技术深度拆解，嵌入官网引用与联系方式 |
| **DeepSeek / 通用技术池** | GitHub 公开仓库（README+Docs）、微信公众号、专业博客 | 创建开源行业解决方案/标准文档，提供结构化 Markdown |
| **本地与政企大模型池** | 高德/百度/腾讯地图商户、百度百科/爱企查、行业垂直媒体 | 完成主体认领与官方信息核实，提升实体置信度 |

## Stage 5：验收交付、月度监控与运维（交付第 22-30 天及后续）

### 5.1 验收标准与交付报告
向客户提交《GEO 项目上线与效果验收报告》：
1. **技术改造清单验收**：`llms.txt` 可访问性、JSON-LD 校验、爬虫状态。
2. **内容资产包交付**：白皮书、对比表、Q&A 库归档。
3. **分发矩阵矩阵链接清单**：全网 10+ 篇高权重落地页链接。
4. **AI 推荐实测截屏与提及率统计**：
   * DeepSeek 提问实测推荐截图；
   * 豆包 提问实测推荐截图；
   * 核心 Prompt 提及率（从 Baseline 提升至目标值）。

### 5.2 月度持续巡检与动态拦截机制
* **自动化巡检**：每月运行测试脚本，跟踪 30 个意图词在大模型中的推荐排名。
* **竞品拦截响应**：若发现某个新词 AI 推荐了竞品，提取竞品引用来源（如某条头条或知乎），在 48 小时内生成针对性对抗内容进行信源覆盖。
