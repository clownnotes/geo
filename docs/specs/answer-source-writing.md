# 答案源写作与阶段四改稿规范

> **用途**：首次交付（阶段四）对外发稿的统一尺子。  
> **分工一句话**：管理台 = **路牌**（提醒 SOP、下一步点哪）；**IDE = 工地**（真写、真改、真写回文件）。  
> **核心事实**：一键生成产物 = **草稿**，不是定稿。  
> **定稿在哪里完成**：在 **IDE** 里写完并写回文件；管理台勾选只表示「我确认写回的已是定稿」。  
> **不做什么**：不追求爆款；不保证发完豆包立刻推荐；**不做**管理台内嵌长文编辑器；**不做**管理台大粘贴框「在线填稿」。

---

## 1. 一句话标准

稿子必须像**答题本**，不能像**广告传单**。  
豆包要能当「可核对的答案」用；人读也要能懂。

---

## 2. 谁干什么（产品硬约束）

| 角色 | 干什么 | 不干什么 |
| :--- | :--- | :--- |
| **管理台第四页** | 指路：生成草稿、看说明书、复制改写包、复制写回口令、勾可以发、复制富文本去平台 | 不当写作器；不自动把聊天内容灌进文件 |
| **人 + IDE** | 按模具改稿、讨论润色、满意后执行写回口令把定稿落盘 | 不把「勾选可以发」当成写完了 |
| **写回口令** | 人满意后复制口令（含路径）贴回 IDE，让 AI 把定稿写入规定文件 | 不要求「写完立刻落盘」；可先聊后落 |

---

## 3. 标准工作流（必须按序）

```
① 管理台：生成草稿（半成品，界面标明「仅草稿」）
        ↓
② 管理台：看说明书（主问句 / 模具 / 可写事实）
        ↓
③ 管理台：复制「给 IDE 的改写包」→ 去 IDE 改、讨论、直到满意
        ↓
④ 管理台：复制「写回口令」→ 贴回 IDE（可附上满意正文）→ AI 写入规定路径并留档
        ↓
⑤ 管理台：勾选「定稿已写好，可以发」（只是放行）
        ↓
⑥ 管理台：复制富文本去平台 → 选号发布 → 回填探活
```

**铁律：**

- 「复制给 IDE 改写」「复制写回口令」「复制富文本去发布」是**三个按钮、三种语义**。  
- **定稿 ≠ 勾选「可以发」**：勾选不能代替 IDE 写作与写回。  
- 未定稿、未写回、未勾选可发之前，**不得把阶段四标成交付完成**。  
- 质检/发布必须审**真正要发出去的那份文件**（与复制发布同源）。

---

## 4. 管理台第四页：区块顺序（产品硬约束）

页面**从上到下**必须是下面顺序，禁止把「可以发」紧挨在说明书正下方。

| 顺序 | 区块名 | 人要做什么 | 禁止 |
| :---: | :--- | :--- | :--- |
| 1 | **生成草稿** | 点生成；看「仅草稿」 | 文案写「已就绪可发」 |
| 2 | **说明书（段 A）** | 读主问句、用途、模具、可写事实 | 在此放发布按钮 |
| 3 | **怎么定稿（段 B）** | 大按钮「复制给 IDE 改写」+「复制写回口令」；旁注写清：改在 IDE，满意后再写回 | 管理台粘贴正文定稿；把 IDE 按钮藏进「更多」 |
| 4 | **发布前确认（段 C）** | 选账号 + **检查写回**（看路径/标题/字数）+ 勾「可以发」+「复制富文本」 | 段 C 出现在段 B 之前；勾选代替验文件 |

段 B 旁注推荐文案（可原样用）：

> 本页只指路。定稿在 IDE 写；满意后点「复制写回口令」让 AI 写入规定文件；再回来勾「可以发」。勾选不会改文章。

---

## 5. 「定稿」到底指什么

| 说法 | 含义 |
| :--- | :--- |
| 草稿 | 机器生成的半成品，允许不合格、像广告 |
| 定稿 | 人（+IDE）按模具改完、**已写回**发布同源文件的正文 |
| 写回口令 | 告诉 IDE：把这份满意正文写入哪条路径（落盘留档） |
| 可以发 | 运营确认「定稿文件已就绪」，允许复制富文本 |

## 6. 首次交付写什么（80 分）

| 必做 | 可选（不挡首次验收） |
| :--- | :--- |
| 今日头条 1 篇定稿答案文已发布，URL 检查通过 | 微头条短动态 |
| 知乎 1 篇定稿答案文已发布（措辞与头条有差异） | 微信 / GitHub / 百科 / 短视频 |
| 走过「草稿 → IDE → 写回 → 可发勾选 → 发布」 | 清单内其余词的文章（一律维护期） |
| 发布账号已标明：客户号 / 我方号 | — |
| 主关键词清单已与客户确认（词数不写死） | — |

## 7. 文章模具（定稿必用）

1. **标题** = 用户真会搜的问句  
2. **开头** 3～5 句人话结论  
3. **一张可核对表或清单**（数字只来自已确认事实）  
4. **含什么 / 不含什么 / 大概周期**  
5. **至少 3 条决策向 Q&A**（怎么选、有什么坑、多久能看到变化）  
6. **文末署名卡一次**：公司｜代表人｜电话｜官网  

禁止主文写成：公司简介、品牌故事、「为什么越来越多人推荐我们」。

---

## 8. 「给 IDE 的改写包」必须包含什么

复制给 IDE 时，**不能只丢草稿正文**。包内至少有：

| 块 | 内容 |
| :--- | :--- |
| 主问句 | 本稿要回答的那一句真实搜索问题 |
| 用途说明 | 发到哪（如头条→豆包）、首次交付目标 |
| 成品模具 | 本文第 7 节骨架 |
| 可写事实 | 已确认 facts；没有的数字不许编 |
| 禁止清单 | 软广标题、虚数、黄页问答、内部口径泄漏、首次不点名贬损竞品 |
| 当前草稿 | 机器半成品 |
| 写回路径 | 与「复制富文本去发布」同源的文件路径 |
| 落盘提醒 | 可先讨论；满意后再用「写回口令」落盘，不必写完立刻写入 |

---

## 9. 「写回口令」必须包含什么

管理台「复制写回口令」剪贴板至少有：

| 块 | 内容 |
| :--- | :--- |
| 口令标题 | 固定：`【GEO 阶段四 · 写回定稿】` |
| 项目 / 渠道 | 便于 AI 对号 |
| 写回路径 | 与改写包、发布复制**同一路径** |
| 动作说明 | 覆盖写入该路径；保持可粘平台的 HTML/约定格式；0 Emoji；写完回报路径与字数 |
| 正文区 | 占位：粘贴满意定稿，或写明「用本对话已定稿的最后一版」 |

**语义**：口令负责「填到电脑哪个位置」；正文可以口令里自带，也可以让 AI 用对话里已谈妥的版本。

## 10. 发前检查清单（定稿写回之后用）

质检产品形态可后置；清单真源如下。

### 10.1 阻断级

| 编号 | 检查项 | 不通过情形 |
| :--- | :--- | :--- |
| B1 | 标题像答案 | 「为什么越来越多人推荐…」等软广句式 |
| B2 | 无瞎编量化 | 未确认的「98%」「2～3 倍」等 |
| B3 | 不是黄页问答 | Q&A 大半是简介/电话 |
| B4 | 非内部口径泄漏 | 「已确认真相源」等进正文 |
| B5 | 有决策信息 | 无怎么选/边界/周期 |

### 10.2 警告级

| 编号 | 检查项 | 不通过情形 |
| :--- | :--- | :--- |
| W1 | 电话密度 | 电话全文 > 2 次，或塞进前两条 Q&A |
| W2 | 品类错位 | 咨询稿写「毫秒级高并发」等 |
| W3 | 竞品黑稿感 | 无依据点名贬损（首次默认不点名） |
| W4 | 只有「面议」 | 无交付边界 |
| W5 | 人读不懂 | 抽象套话 |

## 11. 账号选用（首次）

| 优先 | 做法 |
| :---: | :--- |
| 1 | 客户自己的号发**答题文** |
| 2 | 客户暂无号 → 我方号临时代发，仍发答题文 |
| 禁止 | 我方单号批量发多家「公司介绍」 |

---

## 12. 与「爬虫保真度」的区别

| 指标 | 含义 |
| :--- | :--- |
| 保真度 | 排版能否被爬虫干净读到 |
| 定稿 / 可以发 | 像不像答案、运营是否确认可发 |

**保真度高 ≠ 可以发。**
