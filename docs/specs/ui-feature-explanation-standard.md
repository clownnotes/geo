# ui-feature-explanation-standard.md — 管理端功能解答与引导说明规范

> 本规范定义管理端所有功能页面的顶部说明、引导卡片与文案架构标准，遵循麦肯锡“金字塔原理（结论先行）”，由 AI 助手与开发人员严格执行。

---

## 一、架构设计：麦肯锡 V-W-W-H 认知模型

所有功能模块的顶部解答与引导说明，一律自上而下严格划分为 4 个层级：

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Value (价值结论 · 终局成果)                              │
│    做完能拿到什么交付成果？对业务有什么决定性价值？         │
├─────────────────────────────────────────────────────────────┤
│ 2. What (这是什么 · 定义与边界)                             │
│    通俗比喻定义功能本质，严格划清“管什么、不管什么”。       │
├─────────────────────────────────────────────────────────────┤
│ 3. Why (为什么做 · 痛点与避坑)                              │
│    不做的惨痛代价是什么？为什么不能跳过？                   │
├─────────────────────────────────────────────────────────────┤
│ 4. How (怎么去做 · 极简三步法)                              │
│    操作动线与人机分工闭环（①出题 ➔ ②真问 ➔ ③确认写入）。│
└─────────────────────────────────────────────────────────────┘
```

## 二、视觉系统：四色与排版尺寸规范

### 1. 色彩语义 Token

严格引用 [`docs/specs/geo-admin-ui-tokens.md`](./geo-admin-ui-tokens.md) 的主色定义：

| 认知层级 | 语义定义 | 主题色 | Tailwind 类名 | 视觉特征 |
|---|---|---|---|---|
| **Value** | 价值与交付物 | 系统主色紫 (`--geo-primary: #7c5bf5`) | 底色：`bg-indigo-50/70`<br>左边条：`border-l-4 border-[#7c5bf5]`<br>文字：`text-indigo-950` | 顶层大卡片，强化确定感与业务结晶 |
| **What** | 客观事实与边界 | 冷调蓝灰色 | 底色：`bg-slate-50`<br>左边条：`border-l-4 border-sky-500`<br>文字：`text-slate-800` | 冷静客观，理清边界与概念 |
| **Why** | 警醒避坑与痛点 | 暖调琥珀黄 | 底色：`bg-amber-50/60`<br>左边条：`border-l-4 border-amber-500`<br>文字：`text-amber-950` | 提醒注意思考，警惕盲目施工 |
| **How** | 行动指引与动线 | 通路翡翠绿 | 底色：`bg-emerald-50/50`<br>左边条：`border-l-4 border-emerald-500`<br>文字：`text-emerald-950` | 畅通链路，明确 1-2-3 操作闭环 |

### 2. 颜色红线与边界
- **红色绝对保护**：红色（`rose-*` / `red-*`）保留给系统运行报错、网络断开、表单必填校验失败、不可逆删除等危险场景。**功能引导说明中 100% 严禁出现红色**。
- **浅底 + 侧彩条（Accent Line）**：严禁整块填充大饱和度彩块，统一使用微弱浅底色（`-50` 系列）搭配 `border-l-4` 彩条，克制高级，防止视觉疲劳。
- **Emoji 0 容忍**：严禁使用低幼 Emoji 表情符号。

### 3. 排版与尺寸规范
- **外容器**：`rounded-xl border border-slate-200 bg-white p-4 space-y-3`
- **价值卡片（Value）**：`p-3.5 rounded-lg border border-indigo-100`，标题使用 `text-xs font-bold`，带有高光徽章 `【核心交付成果】`。
- **展开说明列（What / Why / How）**：
  - 标题统一：`text-xs font-bold flex items-center gap-1.5`
  - 正文统一：`text-[11px] leading-relaxed`
  - 序号胶囊：`w-4 h-4 rounded-full text-[10px] font-bold inline-flex items-center justify-center`，使用清晰的 `1/2/3/4` 数字序列。

## 三、文案自检清单（五年级直白白话 · 对齐 plain-speak）

1. **阶段零两件真东西禁混谈条款**：
   - 界面主文案只谈两件真实交付物：**问题清单**（要问豆包的几句话）与 **豆包答案存档**（问完并点过「确认写入」）。
   - **禁止**自造抽象交付物名充当主文案（如「底牌报告」「基线」「剧本」「探活」）。
2. **How 三步与页内 1/2/3 步对齐**：
   - ①出题 ➔ ②真问 ➔ ③确认写入。
   - **禁止**把「落盘豆包结果文件」和「确认写入项目」混为一谈。
3. **动态状态条隔离**：
   - 静态 V-W-W-H 负责功能定性说明；动态状态引导（首轮 vs 再测一遍）由 `modeBanner` 与右上角状态芯片承载，两者绝不互相替代或吞并。
