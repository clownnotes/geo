> **状态**：生效中（战略级架构基线）  
> **适用对象**：所有 AI 助手（Antigravity、Windsurf、Claude Code、Cursor 等）及系统运维人员。  
> **核心使命**：定型 GEO 系统从“家用物理机母体”到“公网商用 VPS”，再到“腾讯云边缘 CDN”的三层架构标准，彻底统一各端认知，杜绝重复讨论与配置反复。

## 一、核心服务端三层拓扑架构

本项目交付的客户企业官网及 GEO 知识底座，采用**“物理机母控 + VPS 商用中转 + 腾讯云边缘 CDN”**的三层交付拓扑：

```
                    ┌────────────────────────────────────────┐
                    │      终端访客 / 大模型联网检索蜘蛛       │
                    │   (Bytespider / DeepSeek / Kimi / 百度) │
                    └───────────────────┬────────────────────┘
                                        │ (访问加速)
                                        ▼
                    ┌────────────────────────────────────────┐
                    │       第一层：腾讯云边缘 CDN            │
                    │  - 全网 Anycast 节点覆盖，极速秒开      │
                    │  - 静态页面与 llms.txt 强缓存 (加速/抗刷)│
                    │  - 自动化 HTTPS 证书与防 DDoS/CC       │
                    └───────────────────┬────────────────────┘
                                        │ (回源商用 IP)
                                        ▼
                    ┌────────────────────────────────────────┐
                    │       第二层：公网商用 VPS 转发        │
                    │  - 具备合法固定公网商用 IP              │
                    │  - 承载域名解析 (A/CNAME) 与合规准入    │
                    │  - 规格多为 3~5 Mbps (适配中小企业客户) │
                    │  - 承担反向代理 (Nginx / 边缘中转)     │
                    └───────────────────┬────────────────────┘
                                        │ (数据同步 / 穿透转发)
                                        ▼
                    ┌────────────────────────────────────────┐
                    │      第三层：家用物理机 (总控母体)      │
                    │  - 硬件：自备 Mac / 物理服务器          │
                    │  - 网络：中国联通动态公网 IP (50M 上行) │
                    │  - 职能：GEO 5步流水线、语料提纯编译   │
                    │  - 特点：零云端高带宽租用成本、掌控一切 │
                    └────────────────────────────────────────┘
```

## 二、三层架构的职能与分工标准

### 1. 家用物理机（总控母体与数据源点）
- **网络特性**：接入**中国联通动态公网 IP**，家庭宽带上传带宽通常为 **50 Mbps**。
- **角色职能**：
  - 作为 GEO 控制台（Web GUI）与流水线核心引擎宿主；
  - 存储全量客户原始素材、知识三元组与事实图谱；
  - 100% 掌控建站编译逻辑，自动生成静态网站（`index.html`）、`/llms.txt`、`robots.txt`、`schema.jsonld`；
- **成本与带宽认知**：
  - 50 Mbps 的公网物理上传带宽极高（相当于每月数千元云服务器独享带宽）。由于 GEO 页面纯文本仅 10~20 KB，50 Mbps 单机每秒可吞吐数百次大模型并发抓取，成本为零。
- **关于环境稳定性的战略定调**：
  - 现代城市电网极度稳定，**架构设计中无需考虑停电假想问题**，杜绝过度设计。

### 2. 公网商用 VPS（合规商用 IP 与转发出口）
- **网络特性**：具备工信部认可的商用固定公网 IP，常规客户配置多为 **3~5 Mbps**。
- **角色职能**：
  - 解决家用宽带无固定 IP、不能直接商用绑定 80/443 端口的限制；
  - 承接客户域名的直接解析（如 `ai.customer.com`）；
  - 作为 Nginx 反向代理网关，将合法公网流量与请求与物理机或本地数据打通。

### 3. 腾讯云边缘 CDN（极速加速与流量防护）
- **角色职能**：
  - 全球/全国节点秒级就近响应，降低大模型爬虫抓取延迟；
  - 消化 99% 的公网访问流量，彻底抹平客户 VPS 3~5 Mbps 的带宽瓶颈。

## 三、静态缓存时机策略（规避调试干扰与发布失真）

针对“静态缓存太死导致改动无法实时显现”的痛点，系统严格遵循**“环境分离与发布定稿再缓存”**的流水线规范：

| 阶段 / 环境 | 访问通道 | 缓存策略 (Cache-Control) | 适用场景 |
| :--- | :--- | :--- | :--- |
| **阶段 1：开发预览态** | 物理机直链 / GUI 调试沙箱 (`http://127.0.0.1:8088/...`) | `no-cache, no-store, must-revalidate` (带时间戳 `?t=now`) | 1~5 步修改素材、重新编译、实时校验，**绝不缓存，改完秒见** |
| **阶段 2：生产发布态** | 腾讯云 CDN / VPS 绑定的商用域名 | 开启静态文件强缓存（HTML 7天，CSS/JS 30天） | 确认定稿上线，全网大模型秒级爬取，抗并发 |
| **阶段 3：内容更新迭代** | 管理台触发【更新发布】 | 自动调用腾讯云 CDN **Purge Cache (一键刷新 URL 缓存)** | 客户信息或 FAQ 变更时，定点清除 CDN 缓存并重载快照 |

## 四、商业落地与实施约束

1. **客户全权代管原则**：
   - 客户无需懂得服务器、反向代理、CDN 与 DNS；
   - 域名、证书、反代、CDN 节点配置 100% 由我方主理人（老白）统筹配置与运维；
   - 客户服务器（VPS）无论是由客户提供还是由我方代购，统一接入上述转发体系。
2. **源码资产兜底机制**：
   - 尽管在架构上由我方平台实行一站式免运维托管，控制台依然保留【一键打包下载整站源码 (.zip)】功能；
   - 此功能作为**客户资产离线归档与保障**，彻底打消客户对“技术被绑定”的顾虑。
