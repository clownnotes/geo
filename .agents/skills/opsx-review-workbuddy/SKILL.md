# WorkBuddy 独立审查与自动修正闭环 (GEO 工作区)

当用户通过 `/opsx-review-workbuddy` 触发此技能时，执行以下**全自动对抗审查与修正闭环**流程：

---

## 核心协作与终验原则
* **角色定位**：WorkBuddy 为独立审查者（Reviewer），Antigravity（反重力）为主力开发与修正者（Coder）。
* **终验标准**：**以 WorkBuddy 最终给出 `[通过]` 标签为唯一验收通过标准**。
* **熔断限制**：修正循环**最多执行 3 轮**；若 3 轮后仍未通过或遇到 `[待讨论]`，立即停止并交由师弟（产品负责人）裁决。

---

## 执行步骤

### 第一步：确认活动变更与审查阶段
1. 运行 `./opsx status` 确认当前活动的 OpenSpec 变更。
2. 判定审查阶段：
   - 若处于方案制定阶段：指定 `--stage design`；
   - 若已有代码修改/Git Diff：指定 `--stage code`。

### 第二步：调起 WorkBuddy 审查
执行桥接审查命令（一次性同步执行完成，直接获取回复，严禁设置定时轮询打扰）：
```bash
./opsx review-wb --stage [design|code]
```
脚本会严格锁定混元 3 免费模型（`hy3`），**严禁调用任何收费模型**。
- 若 `hy3` 免费额度耗尽或受限，脚本会**立即安全阻断**，并在终端输出换号指南，提醒师弟切换免费账号；
- 审查成功后，审查结果自动追加写入 `review-log.md`。

### 第三步：呈现结论与逐项反馈
1. 将 WorkBuddy 输出的审查意见完整呈现给师弟；
2. 汇报已针对意见完成的代码或文档修正点；
3. 由师弟裁决或继续下一步，严禁自主反复死循环消耗算力。

#### 分支 0：遇到 `🔴【免费额度耗尽】` 告警
1. 立即停止自动审查，并在对话中提醒师弟：“混元 3 免费额度已用完，请在 WorkBuddy 切换下一个免费账号”。
2. 等待师弟换号完毕后，再次执行审查。

#### 分支 A：WorkBuddy 给出 `[通过]`
1. 在终端和对话中向师弟播报审查已顺利通过。
2. 流程圆满结束，进入下一阶段（如继续执行 tasks.md 编码或归档变更）。

#### 分支 B：WorkBuddy 给出 `[需修正]` (包含 🔴 必须改 / 🟡 建议改)
1. Antigravity 仔细读取 `review-log.md` 中 WorkBuddy 指出的具体问题与修改建议。
2. 针对性修改代码或设计文档，并完成本地语法/逻辑自检。
3. 自检完毕后，**自动再次调用 WorkBuddy 发起下一轮复审**（返回第二步）。
4. 记录当前循环轮次（Round + 1）。

#### 分支 C：WorkBuddy 给出 `[待讨论]` 或 **循环已满 3 轮**
1. **立即触发熔断**，终止自动修改循环。
2. 整理双方存在分歧的核心焦点与各轮 Review 摘要。
3. 输出给师弟，请求师弟作为产品负责人进行人工裁决。
