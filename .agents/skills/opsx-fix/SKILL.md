# OpenSpec Fix 修复流程

当其他 IDE（如 Cursor、Windsurf 等）完成审查并在 `review-log.md` 中指出了待修正问题（`[需修正]` 或优化项），用户输入 `/opsx-fix` 时执行：

1. **定位审查意见**：
   - 打开当前活动变更的 `review-log.md`；
   - 提取对端 IDE 指出的全部问题（🔴 必须修正项、🟡 建议项）。

2. **区分类型并针对性修改**：
   - **若是方案/设计缺陷**：订正 `proposal.md`、`design.md` 或调整 `tasks.md`；
   - **若是代码实现缺陷/Bug**：直接定位目标业务代码文件进行修复，补齐防御或测试用例。

3. **运行回归验证**：
   - 运行项目相关的体检或测试脚本（如 `check_site_standard.py`、`check_article_styles.py` 等），确保修改不破坏现有功能。

4. **追加共识日志**：
   - 向 `review-log.md` 追加一条记录：
     - 标注 `[已修正]` 或 `[已达成共识]`；
     - 详细说明修改了哪些文件、解决了哪些对端提出的问题及验证结果。

5. **【严格停步约束 (STOP)】**：
   - 修复与验证完成后，**必须立即停步（STOP）**；
   - 简要向用户汇报修改的文件与修复结果，等待对端 IDE 复审或用户验收；
   - **绝对严禁擅自执行 opsx-archive 归档！**
