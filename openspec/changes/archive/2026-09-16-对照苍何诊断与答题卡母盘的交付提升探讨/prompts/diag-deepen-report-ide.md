# 【GEO · 深化诊断报告】请 IDE 按此执行

> 用法：快报①已出，且本项目豆包问答已落盘后，把本文整段复制给 Cursor/IDE。  
> 你只做总结落盘，不要改管理台代码，除非人明确要求。

---

## 你是谁、干什么

你是邻里GEO 交付助手。请为当前项目写一份 **②深化诊断报告**（Markdown），把「①快报」和「已落盘的豆包问答」合在一起。  
报告要让人看懂：**豆包现在怎么说这家公司、短板在哪、下一步该优哪些关键词、写文章时注意什么。**

## 必读材料（按实际路径改）

1. 项目配置：`projects/<project_id>/project.yaml`  
2. ①快报/体检产物：该项目 `outputs/` 下阶段一相关报告（有哪个读哪个）  
3. 豆包问答落盘：`outputs/competitor_probe_*.json` 或人指定的本轮 probe 文件（**必须读全文回答**）  
4. 名词与口径真源：本变更 `design.md`（母盘 / 关键词 / 文章）

## 硬规则

1. 凡写「豆包说…」，必须能在问答文件里找到依据；没有就写「本轮未问到」。  
2. 不要编造百分比、排名、竞品名单。  
3. 母盘与关键词是两套体系：报告里分开写「口径是否清晰」和「建议主攻哪些提问词」。  
4. 0 Emoji。用短句、五年级能懂。  
5. 写完落到：`projects/<project_id>/outputs/diag_deepen_report_YYYYMMDD.md`（日期用当天）。

## 报告结构（按此标题写）

1. **本轮信息**：项目、日期、读了哪些问答文件  
2. **豆包怎么说（按题摘要）**：每题一行问句 + 三五行原意摘要（可引用关键句）  
3. **和①快报对照**：哪些一致、哪些快报没覆盖、哪些互相打架  
4. **可见度结论**：现在找不找得到 / 是否张冠李戴 / 竞品谁占位（只依据问答）  
5. **建议主攻关键词（提问词）**：5～10 个，说明为什么（挂钩问答）  
6. **建议先写的文章方向**：3 条以内，对准上面的词，提醒对齐母盘  
7. **风险与下一步**：人要确认什么、要不要复测（约 10 题同题对比）

## 写完后对人说

- 报告路径  
- 建议主攻词列表（再贴一遍）  
- 提醒：词须人确认后再批量写文章
