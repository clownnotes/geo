## A. 名词：母盘 · 关键词 · 文章（已定）

| 名字 | 是什么 | 不是什么 |
| :--- | :--- | :--- |
| **母盘** | 整家企业的**定位方向**与已确认口径 | 不是某一篇发出去的稿 |
| **关键词**（提问词） | 要抢哪些问法/词条 | 不是缩小版母盘；外人说的「答题卡」≈ 这个 |
| **文章**（定稿） | 按母盘、围着关键词写的可发布正文 | 不是母盘本身 |

流程：母盘齐 → 人选词并客户确认 → 按母盘围着词写文章 → 发布 → 复测。  
硬规则：文章对齐母盘；写前定主攻词；废弃「答题卡」作正式产品名。

母盘与关键词是**两套体系**，不要揉成一份重复清单。

---

## B. 关键词清单 · 首次 vs 维护（已定）

1. 词数**不写死**（按行业与沟通）；合适多少用多少，不强凑。  
2. 母盘不变，维护期可**加词**。  
3. **须客户确认**做哪些词。  
4. **首次文章**：头条 1 + 知乎 1；其余一律维护。  
5. 词多、首次文可先少——清单立住 ≠ 首次写完所有词。

## D. 诊断：①快报 + 可选②深化（已定方向）

| 档 | 说明 |
| :---: | :--- |
| **① 快报** | 现有诊断/体检，出得快；客户不重要时可只出这份 |
| **② 深化** | 可选：问完豆包落盘后，IDE 结合问答出第二份报告 |

- ②提示词：本目录 `prompts/diag-deepen-report-ide.md`  
- 管理台「复制深化提示词」按钮可另排期；现可直接复制该文件给 IDE  
- 落盘要有：日期、项目、引用的问答路径、依据原话的结论（禁止编造「豆包说过」）  
- 单次提问规模约 **10** 题（不作 100）

阶段零 = 问豆包；阶段一快报 = 官网/体检类。不是同一张纸；②把问答结合进报告。

## E. 复测口径（已定）

IDE 开浏览器问豆包等并落盘；约 **10** 题/次。不作必须 100。
