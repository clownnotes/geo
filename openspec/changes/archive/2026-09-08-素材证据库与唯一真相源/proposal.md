# Proposal: 素材证据库与唯一真相源

## Why (为什么做)

### 现状痛点（已在 nextgeo Step 3 实操确认）

1. **官网抓取是单页覆盖，不是证据累积**  
   - `POST .../ingest/url` 每次只抓用户填写的那一个 URL；  
   - 正文固定写入 `raw_materials/website_crawled_raw.md`，再抓一页就**整文件覆盖**；  
   - 多页官网（首页 / 关于我们 / 产品 / 价格）无法形成可追溯证据链，上一页有用信息直接丢失。

2. **缺少「唯一真相源」层**  
   - 当前只有「原料文件」+「每次全量重算并覆盖的 `raw_extracted_facts.md`」；  
   - 事实清单不带来源 URL、抓取时间、原文摘录、客户确认状态；  
   - 冲突数字会被静默盖掉，无法人工仲裁——对 GEO 引用可信度是硬伤。

3. **交付物与原料耦合不清**  
   - 普林斯顿语料、实体图谱、RAG 分块、站点 Schema 理论上应消费「已确认事实」；  
   - 实际容易误以为「抓一次网址 = 改一次下面语料库结论」，产品心智混乱；  
   - 语料库仅在点「执行普林斯顿重构」时更新，但 UI 未把「证据 / 真相 / 交付」三层说清楚。

4. **为什么这对 GEO 有商业价值**  
   - 大模型采纳与引用依赖可核验、口径一致的实体与量化事实；  
   - 没有 SSOT，多页抓取与多渠道发稿会口径漂移，监测阶段无法解释「AI 为什么这么说」；  
   - 交付验收需要「事实可溯源到客户官网/手册」——覆盖式单文件无法支撑验收与合规。

5. **续议痛点（真相源会变是正常的，但全量重生母盘有 GEO 风险）**  
   - 客户持续补料 → 真相源更新很正常；  
   - 但每次「执行普林斯顿重构」若整篇 LLM 重生，措辞/结构抖动会让外发口径与监测引用不稳；  
   - 硬矛盾（同键异值）已可识别；近义重复、跨键逻辑矛盾、相对「上一版已钉外发稿」的差异，仍缺少产品化对照。

### 目标结论

保留「单次抓取可覆盖该来源」的简单心智，但必须补齐：  
**证据可多份累积；真相源唯一、可合并、可溯源；交付物只认真相源。**

并在同一变更内续完：  
**真相源可变 → 母盘按脏块增量更新；发前对照上一钉住版本；矛盾/重复可识别并给策略建议（补丁 vs 新文）。**

## What Changes (改动了什么)

### A. 已落地（证据库 / 真相源底座）

1. **证据库（Evidence Vault）**  
   - 每个抓取 URL / 每次粘贴补充，各存一份证据文件（按来源键命名，可重抓覆盖**该来源**，不覆盖其他来源）；  
   - 废弃「全站共用一个 `website_crawled_raw.md`」作为唯一官网稿。

2. **唯一真相源（Canonical Fact Ledger）**  
   - 以结构化事实条目（键、陈述、来源、摘录、状态）替代「整份 Markdown 盲覆盖」；  
   - **标准事实键字典（Standard Keys）**约束提取与合并，防止同义不同键导致冲突判定失效；  
   - 新证据入库后对真相源做**按键合并**：新增 / 修订提案 / 冲突待确认；  
   - 仅「已确认」事实进入 rewrite / graph / RAG / schema 消费路径；冲突未决时降级沿用历史 confirmed 或安全占位，严禁静默编造。

3. **Step 3 工作台心智与 UI**  
   - 明确三栏或三态：证据列表 → 真相源（含冲突队列）→ 交付物预览；  
   - 支持「一键确认所有无冲突项」；冲突项必须人审仲裁；  
   - 抓取/粘贴不再暗示「下面语料库已自动改完」；重构按钮文案与前置条件对齐「需已确认真相源」；  
   - UI 遵循 `AGENTS.md`：Lucide 图标 + 语义 Tag，严禁彩色 Emoji。

4. **兼容迁移**  
   - 存量 `website_crawled_raw.md` / `product_supplement.md` / `raw_extracted_facts.md` 一次性迁入新结构；  
   - ledger 更新时**自动同步刷新**根目录 `raw_extracted_facts.md` 兼容镜像，避免外部未升级脚本 `FileNotFoundError`；  
   - CLI `geo ingest` / `geo facts --confirm-all` 与现有 API 保持可调用，语义升级为「写入证据 + 提案更新真相源」。

### B. 续完善（本变更未完成项，待审后 apply）

5. **母盘脏块增量重构**  
   - 母盘按块绑定事实键族（定义 / 对比表 / FAQ / 承诺联络等）；  
   - 仅当对应 `confirmed` 事实集合相对母盘指纹有变更时，标记脏块并只重生脏块；无脏块则跳过或提示「母盘已是最新」；  
   - 核心数字与主体尽量模板直出，降低 LLM 抖动。

6. **矛盾 / 重复识别增强**  
   - 硬矛盾：同键异值（已有 `conflict`）；  
   - 软重复：近义陈述聚类提示合并；  
   - 跨键规则：如服务区域互斥等少量业务校验 → `logic_conflict` 待审。

7. **发前对照卡（相对上一钉住版本）**  
   - 新母盘 / 待发稿 vs 上一 `pinned` 外发快照：事实层 diff + 块层脏块 + 策略建议（静默补丁 / 需新开文 / 先仲裁）；  
   - 人确认后才进入阶段四；已外发 URL 不因工作母盘覆盖而静默替换。

## Capabilities (新增或修改的对外能力)

**已具备：**
- 证据库：按来源列举 / 查看 / 删除 / 重抓覆盖单来源  
- 真相源：列出事实、单条确认、`confirm-all`、冲突仲裁、`facts.md` + `raw_extracted_facts.md` 双视图导出  
- ingest URL/Text：写入证据后返回「新增/修订/冲突」摘要  
- rewrite 及下游：只消费 `confirmed`；冲突/无确认时明确降级提示  

**续完善后新增：**
- `GET/POST .../corpus/dirty-blocks`：计算脏块与 facts_hash  
- `POST .../rewrite` 支持 `mode=incremental|full`（默认 incremental）  
- `GET .../corpus/diff?against=pinned`：发前对照卡数据  
- `POST .../corpus/pin`：钉住当前母盘为外发对照基线  
- 真相源：重复簇 / 逻辑矛盾列表与处理动作

## Impact (受影响的部分)

| 区域 | 影响 |
| :--- | :--- |
| `tools/geo/ingest.py` / `ledger.py` | 证据落盘、合并、（续）重复/逻辑矛盾 |
| `tools/geo/rewrite.py` | （续）脏块增量、模板直出核心块、版本指纹 |
| `tools/geo/server.py` / CLI | CRUD +（续）diff/pin/incremental rewrite |
| `web/index.html` Step 3（→4 衔接） | 证据/真相源 UI +（续）对照卡 |
| `docs/sop/03-rewrite-sop.md` | 素材→真相→增量重构→发前对照 |
| 存量 `raw_materials/` / `outputs/` | 迁移；母盘增加 fingerprint / pin 元数据 |

**不做（本变更边界外）：** 全站递归爬虫、自动覆盖已发布线上 URL、付费媒体投稿链路改造。
