# Proposal: 阶段一商业诊断升级3竖列工作区

## Why (为什么做)
1. **单页聚焦原则**：遵照师弟「一页一页做」的最高指示，不再搞多阶段打包大改，死磕并做透「阶段一：AI 可见度商业转化诊断」。
2. **场景动线对齐真实业务**：原阶段一虽然按钮齐全，但堆叠在一个卡片中，没有体现出“抓底座指标 -> 与客户对照 -> 客户耐心门禁判定 -> 出具初稿 -> 外部 IDE/豆包润色贴回 -> 出具多版本最终报告”的真实作业流水线。
3. **保持阶段零一致的专业体验**：把阶段一全面升级为阶段零相同的「3 竖列工作区」（左栏资产树 + 中栏多 Tab 编辑打磨 + 右栏 SOP 动线 + 顶部看板与麦肯锡手册），既保留原版的所有功能，又让交付专家操作体验丝滑直观。

## What Changes (改动了什么)
1. **左栏（资源管理器 StudioFileTree）**：
   - 细分为三大文件分类：
     - **指标与素材**：`01_网络底座指标_待对照.md`、`01_阶段零豆包问答素材.md`
     - **过程草稿**：`01_商业诊断与转化初稿.md`（支持复制到外部润色后贴回）
     - **最终交付报告**：`01_老板商业诊断报告_好看大屏.html`、`01_老板商业诊断报告_文字版.md`、`01_工程师底座技术审计.md`
2. **中栏（多 Tab 在线打磨区 StudioEditor）**：
   - 支持多 Tab 自由切换与关闭；
   - 支持 Markdown 源码编辑、高保真渲染预览；
   - 针对《好看大屏.html》支持 HTML 实时预览与全屏演示；
   - 顶部具备【一键复制内容】（带去外部 IDE 润色）与【保存文件】按钮。
3. **右栏（SOP 交付动线流水线 StudioSop）**：
   - **步骤 1：真抓底座指标与客户对照**
     - 操作：点击【真抓网络底座指标】（直出机械基础信息，中栏可直接微调修改）；
     - **耐心判定门禁**：明确提供【客户已核对确认（推进下一步）】与【客户暂无耐心/意向不足（挂起等待，暂不推进）】分支，把控签约意向门禁。
   - **步骤 2：生成初稿与去水润色**
     - 操作：点击【直出商业诊断与转化初稿】；
     - 提供润色指引卡：提示“可直接在中栏一键复制初稿与豆包问答底牌，前往外部 IDE 或豆包润色去水，改完贴回保存”；
     - 推进按钮：【初稿润色完成，前往生成最终报告】（亦支持【不优化直接出报告】）。
   - **步骤 3：出具多版本交付报告**
     - 操作：点击【一键生成多版本诊断报告】；
     - 中栏自动加载并打开《好看大屏版》与《商业文字版》；
     - 提供【全屏演示大屏】与【复制客户报告链接】。
   - **步骤 4：交付验收与流转**
     - 验收无误后，点击【完成阶段一，前往阶段二：交钥匙官网】。
4. **顶部与手册配套**：
   - 顶部 `StageHeader` 专属展现阶段一的核心目标与交付备忘录；
   - `MckinseyDrawer` 麦肯锡手册深度沉淀“基于真抓贩卖焦虑、算清 3 类询盘流失账、促成签约”的认知指导。

## Capabilities (对外能力)
1. **客户意向门禁把控**：明确支持客户耐心不足时优雅挂起流程，不强行产生冗余草稿。
2. **白盒外部润色闭环**：初稿在线复制、豆包问答底牌联动、贴回保存的一体化流畅体验。
3. **多版本报告一站式查阅**：老板视觉大屏（HTML）、老板商业文字版（MD）、工程师体检版（MD）同屏无缝切换。

## Impact (影响范围)
- 仅影响阶段一（`step-1-diag`）的前端呈现与 Vue3 挂载；
- 阶段 2 至阶段 5 原版 DOM 保持 100% 原始状态不动；
- 不碰后端 `server.py` 与 `data/projects.json`。
