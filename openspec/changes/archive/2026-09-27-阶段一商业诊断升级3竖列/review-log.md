### 二、发现的问题

#### 🔴 问题 1：阶段零的 SOP 动线面板已经被搞坏（线上实际故障，非本次变更引入）

**实测证据**（2019PRO Safari 只读探测）：

```
sopText    = "交付动线 第 1 / 0 步"
sopButtons = 0
```

**根因**：`assets/step0/step0.js` 是「**新版 StudioSop + 旧版 Step0App**」的混血产物。

- `StudioSop.vue`（现为通用版）声明 `stageMeta: { type: Object, required: true }`；
- 而产物里的主应用是旧版 `Step0App.vue`，**根本没传 `stageMeta`**；
- 于是 `steps = stageMeta?.sopSteps || []` 求值为空数组；
- 结果：右侧动线面板只剩标题栏，**所有操作按钮全部消失，用户无法推进任何步骤**。

这是上一轮「全阶段升级3竖列工作区」变更**回档不彻底**留下的残留（该变更已归档）。
**阶段零是当前唯一被破坏的阶段，必须先修。**

#### 🟡 问题 2：新组件与旧主应用的接口全面错配

即使补上 `stageMeta`，事件也对不上：

| 组件 | 新版 emit | 旧版 Step0App 监听 | 后果 |
|---|---|---|---|
| `StudioSop` | `proceed` / `gotoStep` / `extraAction` | `switch-step` / `refresh-questions` / `proceed-to-next` / `finish-stage0` | 按钮点了无反应 |
| `StudioEditor` | 新增 `fullscreen` | 未监听 | 全屏按钮无反应 |

`StudioEditor` 的 `renderMode` 有默认值 `'code'`，可降级工作，属可接受。

#### 🟡 问题 3：本次设计缺少 `stageMeta` / `sopSteps` 定义（会导致重蹈覆辙）

design 第二节只定义了 `STAGE_1_FILES`（文件资产），
**没有定义阶段一的 `stageMeta` / `sopSteps` 结构**。
而现有 `StudioSop.vue` **强依赖 `stageMeta`**（`steps` 完全从 `stageMeta.sopSteps` 取）。

**若照现有 design 直接开工，阶段一右侧动线面板同样会是空的** —— 与问题 1 同一个坑。

**开工前必须补**：在 design 中明确阶段一的 `stageMeta` 结构（含 `sopSteps` 数组、每步的 `name` / `desc` / `category` / `nextLabel`，末步 `isFinal`）。

#### 🟡 问题 4：产物输出路径未规划，有互相清空风险

`step0-src/vite.config.js` 里 `outDir: '../assets/step0'` 且 `emptyOutDir: true`。

design 第四节说阶段一「单独挂载轻量 Vue3 实例 `#step1-app-root`」，但**没说产物输出到哪**。
若阶段一产物也输出到 `assets/step0/`，`emptyOutDir` 会**把阶段零的产物整个清空**。

**开工前必须定**：阶段一产物独立目录（如 `assets/step1/`），或改为多入口构建。

#### 🟡 问题 5：CSS 产物存在但 index.html 未引用

`assets/step0/geo-step0-island.css`（1663 B，内容为 `.geo-md` Markdown 排版样式）存在，
但 `index.html` 中引用数为 **0**。
后果：一旦用到 Markdown 渲染预览态，排版样式会丢失。

#### 🟢 问题 6：阶段 2~5 完好无损

线上实测 5 个面板（`step-2` ~ `step-5`）：
均**无挂载点残留、无隐藏子元素**（`hiddenChildren: 0`），按钮数正常（12 / 16 / 45 / 14）。

**符合 design「阶段 2~5 保持 100% 原始」的要求。** ✅

### 二、本轮新发现的问题

#### 🟡 问题 1：点「步骤头部」跳转时，中栏不联动打开对应文件（交互不一致）

**实测证据**：

```
点击「真抓网络底座与客户对照」步骤头部
beforeStep: 第 2 / 3 步  →  afterStep: 第 1 / 3 步   ✅ 步骤号已切换
beforeFile: 指标与素材/01_阶段零豆包实测问答素材.md
afterFile:  指标与素材/01_阶段零豆包实测问答素材.md   ✗ 中栏文件未跟随
```

预期：应切到第 1 步的 `activeFile`（`01_网络底座指标_待对照.md`）。
二次验证同样复现：跳到第 1 步后，中栏仍停留在「最终交付报告/01_老板商业诊断报告_好看大屏.html」。

**根因**：`useStep1.js` 的 `handleGotoStep(stepNum)` 只改 `currentStep` 并 `saveState()`，
**未调用 `handleSelectTab(step.activeFile)`**；而 `handleProceed()` 是有调用并切文件的。

**后果**：用户点「下一步」和点「步骤头部」到达同一步，中栏内容却不同 —— **两条路径行为不一致**。

**修复方向**：在 `handleGotoStep` 内读取 `STAGE_1_META.sopSteps[stepNum - 1]?.activeFile` 并调用 `handleSelectTab`。

#### 🟡 问题 2：全局事件监听未清理，存在监听器累积隐患

`useStep1.js` 50–54 行在 composable 内直接注册全局监听：

```js
if (typeof window !== 'undefined') {
  window.addEventListener('geo-toggle-step-overview', (e) => { ... });
}
```

**没有对应的 `onUnmounted` 移除**。每次组件挂载都会新增一个监听器。

当前因 `__GEO_STEP1_MOUNTED__` 标记避免了重复挂载，实际风险有限；
但一旦发生强制 remount，监听器会持续累积（内存泄漏 + 重复执行）。建议补 `onUnmounted` 清理。

#### 🟢 问题 3：`dir` 兜底遍历是永不执行的死代码

`stage1Config.js` 232–237 行：

```js
Object.keys(files).forEach((fn) => {
  if (!files[fn].dir) { files[fn].dir = CATEGORY_DIR_MAP[files[fn].category] || '交付文件'; }
});
```

六个文件对象**均已显式赋 `dir`**，故 `if` 条件永不成立，这段代码**从不执行**。

违反 RULES 0.3「禁止打补丁」与 4.3「唯一真相源（同一逻辑只能有一份）」。
建议二选一：删掉遍历；或删掉六处显式赋值、改为遍历统一赋（后者更省事，推荐）。

#### 🟢 问题 4：`localStorage` 超配额时静默失败，用户无感知

`saveState()` 以 `try { ... } catch (_) {}` 完全吞掉异常。
若文件内容增大至超出 `localStorage` 配额（通常 5MB），保存会失败且**没有任何提示**，
用户会误以为已保存。

当前六个文件合计约 5.2 KB，暂无风险；建议至少在 `catch` 中 `console.warn`，或向用户提示保存失败。
