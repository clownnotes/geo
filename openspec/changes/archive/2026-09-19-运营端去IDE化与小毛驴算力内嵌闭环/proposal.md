# Proposal: 运营端去IDE化与小毛驴算力内嵌闭环

## Why (为什么做)
1. **核心商业机密（Prompt 配方）外泄风险极高**：
   - 当前在阶段零（摸底体检）和阶段四（渠道分发定稿）中，广泛存在“复制改写包给 IDE”、“复制写回口令贴回 IDE”、“复制商业初稿与提示词给 IDE 润色”等操作。
   - 运营人员只要点击按钮，就能直接将平台最核心的普林斯顿 9 因子提示词、改写指令、质检判据全部拷进剪贴板。一旦运营人员带着这套 Prompt 配方离职，极易低成本快速复刻并单干。
2. **操作割裂且反直觉**：
   - 负责写文的运营同事大多不是工程师，让他们打开外部 IDE（Cursor / VS Code）、找地方贴提示词、再复制代码贴回终端执行 python 落盘命令，学习成本极高且极易出错。
3. **未发挥自有算力闭环优势**：
   - 平台已具备同机部署的小毛驴大模型（`:3001`）统一代理与调度能力，完全可以直接在服务端调用算力出稿，无需把生成工作丢给外部工具。

必须彻底砍掉“一键复制找 IDE”流程，让运营人员在网页端直接得到小毛驴生成的备选稿，在线修改微调后直接保存，将核心 Prompt 和算力牢牢锁死在系统内部。

## What Changes (改动了什么)
1. **运营端全面去 IDE 化，隐藏底层提示词包**：
   - 移除面向运营人员的“复制改写包去 IDE”、“复制写回口令贴回 IDE”、“追加提示词给 IDE 参考”等暴露底层配方的剪贴板按钮。
   - 底层 System Prompt、改写指令与 9 因子质检规则 100% 收口在后端 Python，前端仅作为展示和编辑窗口。
2. **内嵌小毛驴 AI 算力直出（提供内容备选项）**：
   - 运营人员在阶段四页面点击【小毛驴 AI 智能改写】（或由流水线自动生成预置备选稿），服务端直接调用小毛驴大模型（Nextdoor open API）执行改写。
   - 前端直接呈现改写后的内容（初稿/备选项），运营人员只看到最终文本，看不到背后的 Prompt。
3. **网页内置轻量编辑与一键保存定稿**：
   - 提供直接可编辑的文本编辑区（Textarea / Markdown 实时预览），运营人员在小毛驴生成的内容基础上做人工优化、语句通顺微调、补充事实细节。
   - 点击【保存定稿】按钮，直接通过 API 提交到后端。落盘路径只由服务端渠道表决定（今日头条、知乎现有写回文件），请求里不许带文件名。保存后点亮「已定稿，可以复制发布」。
4. **开发者与运营人员权限与视图分级**：
   - 开发者角色（developer）在需要调试时仍可通过后台接口查看底层 Payload；
   - 运营人员角色（operator）的前端视图完全屏蔽 IDE 概念，仅保留“AI 备选稿 → 在线润色修改 → 保存定稿发布”的流水线标准动作。

## Capabilities (新增或修改的对外能力)
- **Prompt 零外露**：运营人员无法通过任何按钮、接口或小毛驴对话复制出系统的完整提示词包。
- **纯网页端写作闭环**：写文运营人员无需安装或打开任何外部 IDE，即可一站式完成从 AI 生成到人工定稿落盘的全流程。
- **小毛驴算力绑定**：文案生成完全依赖后端小毛驴算力中枢，离开平台账号无法独立运转。
- **炸鸡师傅工位**：分出去的运营账号只能在被分配的客户上，处理眼前这一篇稿。不能单干，也不能借小毛驴把源码和整库内容爬走。

## 炸鸡师傅铁律（师弟 2026-09-19 口令）

运营账号像肯德基的炸鸡师傅：只在自己工位上炸当下这一单。配方、整店食材库、灶台图纸都不许带走。店里的机器人（小毛驴）也不许被他拿来把这些问出来。

**工位上允许做的：**
1. 只看见自己被分到的客户，以及眼前这一篇渠道稿。
2. 点按钮，让小毛驴只改这一篇。人只看到改好的正文，看不到背后的做法。
3. 在网页里改字、保存这一篇。
4. 把这一篇复制出去发布。发稿必须带正文，带走这一篇不等于搬走厨房。

**工位上禁止做的：**
1. **配方**：提示词、成品模具、禁写条、写回路径、质检口令，一律不进运营的页面、剪贴板和接口响应。
2. **用 AI 当爬虫**：运营不能写自由指令。小毛驴只接受服务端写死的「改这一篇」任务。若模型把配方、源码、文件清单或别的客户资料吐出来，服务端直接丢掉，不返回给浏览器。
3. **整包内容**：运营不能下载整站压缩包、验收包、全量导出，也不能随便翻 `outputs/` 里的语料库和其它文件。
4. **源码与机房**：运营不能看仓库代码、Python、Nginx 配置，也不能把这些交给小毛驴去总结。

## Impact (受影响的部分)
- `web/index.html`：
  - 改造阶段四“段 B · 怎么定稿”界面：将原本的“IDE 工地 / 复制改写包 / 复制写回口令”卡片重构为“小毛驴 AI 智能润色 / 在线编辑修改 / 一键保存定稿”视图；
  - 改造阶段零中暴露提示词的“复制给 IDE 润色”等辅助按钮。
- `tools/geo/server.py` 与 `tools/geo/llm.py`：
  - 新增 `POST /api/projects/{id}/answer-rewrite/ai-generate`。走现成的 `resolve_llm_runtime()` + `call_nextdoor_chat()`，不另造一套客户端。
  - 新增 `POST /api/projects/{id}/answer-rewrite/save-final`。只写渠道表里已有的那几个文件。
- `tools/geo/rbac.py`：
  - 配方口和整包压缩下载改为仅开发者可调。清单以 `design.md` 第 4 节为准。
  - 不把「真机要问的那几句话」（`/monitor/prompts`）误锁成配方。
  - 不把运营正在看的客户报告整夹产出文件全部 403，否则流水线没法干活。语料库、9 因子文件、提示词文件仍然不给运营读。
