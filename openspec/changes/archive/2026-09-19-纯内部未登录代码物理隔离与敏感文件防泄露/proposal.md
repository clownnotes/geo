# Proposal: 纯内部未登录代码物理隔离与敏感文件防泄露

## Why (为什么做)
本项目为纯内部专用的 GEO 交付与 SOP 流水线管理工作台，**不对外开放公开注册，禁止任何未经授权的人员嗅探内部业务逻辑**。
在对当前系统进行安全排查后，发现两大致命的代码与信息泄露漏洞：
1. **前端“假隐藏”泄露全量内部源码**：整个管理端单页（15,548 行、1.05 MB）全部集成在单一的 `web/index.html` 中。未登录用户访问 `/` 时，服务器直接将全部 HTML 与内部 JS 代码发往浏览器，仅靠前端 CSS `class="hidden"` 进行视图隐藏。任何未登录用户通过右键“查看网页源码”或在 F12 控制台删除 `hidden`，即可完整获取全站 DOM 结构、SOP 流水线、提示词模板和内部私有 API 地址。
2. **后端静态兜底机制（`super().do_GET()`）导致敏感文件被直接下载**：后端服务继承自 `SimpleHTTPRequestHandler`，在路由未匹配时无差别回落至 `super().do_GET()`，将项目根目录下文件全部暴露。经实测，未登录访客直接在浏览器输入 `/.env`、`/tools/geo/server.py`、`/AGENTS.md` 等路径，服务器均返回 200 并直接将包含大模型 API Key 密钥与后端源码的文件下发。

必须彻底治理上述漏洞，确保外部未授权访客在进入系统前：**既看不到后台图纸，也摸不到敏感文件**。

## What Changes (改动了什么)
1. **一道总门，默认拒绝**（详见 `design.md`）：
   - 每个请求先过门。不在「登录白名单」里、又没有有效登录，一律不进业务代码。
   - 要网页：只给 `web/login.html`。要文件或接口：404，不返回内容。
   - 废除 `super().do_GET()`。不再用「黑名单后缀」或「公开目录」当主防线。
2. **不登录只允许登录**：
   - 登录页、登录接口、扫码登录接口、退出登录。
   - 不含工作台、不含 `.env`、不含源码、不含花名册、不含 `/docs`、不含 `/sites`、不含本机自动登录。
3. **已登录才给工作台** `web/index.html`，再按现有花名册限制能看哪些客户。

## Capabilities (新增或修改的对外能力)
- **不登录只看见登录框**：管理台这台服务上，没有登录就拿不到工作台、源码、密钥、花名册、客户站页面。

## Impact (受影响的部分)
- `tools/geo/server.py`：改造根路由 `/` 的响应逻辑，增加登录态判定分流；收口默认静态兜底为严格白名单。
- `web/login.html`：新建独立轻量登录页面。
- `web/index.html`：清理冗余内嵌登录 DOM 与事件绑定，聚焦于已授权登录后的工作台交付主流程。
- **副作用（须产品接受后再编码）**：管理台上的客户官网 `/sites/`、公开文档、客户报告免登录链接、本机打开即自动登录，都会关掉。客户官网要给外人看，须另放一台只有网页文件的服务。
