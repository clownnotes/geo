## 2026-09-20 Cursor `/opsx-review`：对照产品两问 + 仪表盘场景闭环审查

### 一、产品两问：方案怎么写的、代码是否对得上

#### 问 1：真机实测是谁来测？谁来变成红黄绿灯？

| 环节 | 主体 | 怎么做 | 代码锚点 |
| :--- | :--- | :--- | :--- |
| **测（输入）** | **运营同事本人** | 真机/浏览器打开豆包等客户端提问，把回答全文复制回填 | `POST /api/projects/{id}/monitor/manual-ingest` → `log_manual_ingest` 写入 `data/ops_check_logs.jsonl` |
| **打灯（判定）** | **系统自动**，人不手点颜色 | 看「距上一次有效真机回填」过了多少天 | `tools/geo/check_ledger.py` → `classify_status()` |

默认阈值（可在通知设置改）：

- 从未回填 → `never`（从未真机）
- ≥14 天 → `overdue` 红灯
- 7～14 天 → `warn` 黄灯
- ＜7 天 → `ok` 绿灯

**审查结论**：方案写的「人测、机打灯」与现网代码一致，不是新发明。仪表盘运营侧应消费这套状态（`never`/`overdue` 进「待真机」），不要让运营再去点「机器全量巡检」。

#### 问 2：哪家企业在豆包里「排名不降」？排名怎么找到的？

| 环节 | 谁做 | 怎么做 | 代码锚点 |
| :--- | :--- | :--- | :--- |
| **排名从哪来** | 系统解析回填/巡检文本 | 清洗 Markdown → 按 `1.`/`一、` 等切段 → 匹配客户品牌名落在第几段；有「首推/强烈推荐」语境则 Rank 1；未提及 Rank 0 | `tools/geo/monitor.py` → `parse_probe_text()` |
| **「降没降」怎么判** | 系统对比时序 | SOV 写入项目 `history.db`；`check_alert_conditions`：SOV 低于阈值、环比突降 ≥15%、或核心词失守 Top1 | `tools/geo/patrol.py` |

**审查结论**：底层「怎么找到排名 / 怎么发现暴跌」方案对齐正确。但——**运营仪表盘 UI 目前并没有一张卡直接回答「哪家企业排名不降」**；运营看板设计的是「真机是否逾期」+「交付阶段是否做完」，声量/排名异动只在 Why/What 口头提到，design 四宫格却改成了「已结案企业」。

### 二、能否解决「运营用仪表盘」的场景？

**方向对，闭环未齐。**

能盖住的痛点：

1. 角色错位：开发者看财务大盘，运营不看金额/ROI（方案 A/B 都能脱敏）。
2. 「今天该真机谁」：可用台账 `never`/`overdue` 聚合成待办（方案 A 更直接）。
3. 机器巡检 vs 真机回填：tasks 要求弱化全量巡检文案——对。

尚未盖住 / 文档打架：

1. **方案 A vs B 未拍板**（tasks 1.1 仍空）。不拍板无法进入 apply。
2. **指标口径不一致** 🔴：
   - `proposal` What：待补真机 / 阶段未完 / **声量异常数**
   - `design` 四宫格：待真机 / 未完成交付 / **已结案企业**
   - Why 原话关心「声量告警」，design 丢掉了「声量异常」入口。
3. **「排名不降」未落到运营待办行** 🟡：机制有，看板没有「按企业展示当前豆包位次 / 是否异动」的字段约定；若产品要运营一眼看出「哪家掉了」，须在 design 的 `ops-action-list` 行模型里写清（例如：企业名、真机灯色、最近 Rank/SOV、是否告警、一键进流水线）。
4. 文案：tasks 已要求禁 Emoji、禁「SOP」主文案——保留；design HTML 注释里仍有「SOP」字样，落地时界面应用「未完成交付 / 已结案」。

### 三、建议拍板项（请产品 + 对端确认）

1. **路线**：推荐继续 **方案 A**（运营需要多企业卡点总览；方案 B 省事但回答不了「今天先干哪家」）。
2. **第四格指标**：二选一写死进 design——

3. **待办行是否展示豆包排名/异动**：若要，补一行字段表；若本轮只做真机逾期+阶段卡点，则在 proposal 明确「排名不降属底层机制说明，本轮仪表盘不展示，异动仍走运维告警页」。
