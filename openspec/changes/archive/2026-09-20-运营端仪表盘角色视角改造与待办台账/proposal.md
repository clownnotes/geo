# Proposal: 运营端仪表盘角色视角改造与待办台账

## Why (为什么做)

当前系统仪表盘页面（`panel-home-dashboard`）无论登录者是开发者/管理员还是基层「运营同事」，均共用同一套展示模板。
经过现网线上截屏与代码审计，暴露出以下三个核心业务与架构痛点：

1. **角色视角错位与信息冗余**：
   - 当前仪表盘核心卡片展示「全域商业总价值（如 ¥231,360 元）」与「组合 ROI（如 +1277.1% (13.77x)）」。
   - 商业总估值与投资回报倍数属于管理层、销售与投资人关注的财务指标。基层运营人员的主要日常职责是执行企业交付流水线（关键词摸底、真机实测、提纯资料、生成文章与监测声量）。展示商业估值既无任何作业指导意义，又可能引入商业机密泄露与薪酬心理偏差风险。
2. **缺乏行动指引与待办闭环**：
   - 运营人员登录系统后，最关心的核心问题是：「我管辖的哪家企业今天需要真机实测？哪家企业的豆包答案尚未沉淀？哪家企业声量告警 / 排名掉了？」
   - 当前仪表盘仅展示静态总数（如托管项目 1、全套交付完成 1），没有提供直达流水线作业的今日待办流与卡点提示。
3. **机器巡检与真机实测认知混乱**：
   - 仪表盘常驻提示「最近机器全量巡检：尚未执行」，容易让基层运营误以为需要手动触发并发巡检（实际上巡检由后台定时任务或机器人执行），淡化了运营人员真正需要执行的「真机手机端实测提问与答案回填」动作。
4. **按钮语义不清**：
   - 部分操作按钮名称偏内部用语，运营一眼看不出「点下去会干什么、下一步该怎么做」，需要就地帮助说明（白话提示），而不是另开说明书。

## What Changes (改动了什么)

### 已拍板实施路线：**方案 A（工作台大盘角色裂变）**

方案 B（运营登录直达企业管理、隐藏仪表盘）**本轮明确不采用**。

- 保留仪表盘入口，界面严格根据当前登录角色实行物理渲染隔离；
- **开发者/管理员视角**：保留「全域商业总价值」、「组合 ROI 驾驶舱」、「合作方分布」与全站「真机检测总台账」；
- **运营同事视角**：彻底移除所有金额与 ROI 估值卡片，替换为「今日作业待办看板」：
  - 四宫格：**我的管辖企业** / **待真机实测** / **未完成交付** / **声量异常数**（第四格固定为声量异常，不用「已结案企业」）；
  - 管辖企业快捷待办列表：每行展示真机灯色、最近豆包位次 / 声量、是否异动、一键进流水线；
  - 易混淆按钮与指标旁附白话帮助（`title` / 小字说明 / 问号气泡），让运营知道「这是干什么的」。

### 产品拍板摘要（2026-09-20）

| 决策点 | 结论 |
| :--- | :--- |
| 路线 | **方案 A** |
| 第四格指标 | **声量异常数** |

## Capabilities (能力与系统事实对齐)

### 1. 真机实测与红黄绿灯台账机制
- **测量主体**：运营人员使用真实手机或浏览器打开豆包等大模型客户端提问关键词，并将回答全文复制后回填至系统（`/api/projects/{id}/monitor/manual-ingest`）；
- **打灯主体**：由系统根据上一次有效真机实测距离当前时间的 UTC 天数自动判定状态：
  - 绿灯（正常 `ok`）：距离上次实测小于 7 天；
  - 黄灯（将逾期 `warn`）：距离上次实测达到 7~14 天；
  - 红灯（已逾期 `overdue`）：距离上次实测超过 14 天；
  - 从未真机（`never`）：项目从未进行过真机回填记录。

### 2. 豆包排名提取与声量告警机制
- **排名定位**：通过 `parse_probe_text()` 解析豆包回答文本，识别首推语境及序号列表，自动定位客户品牌推荐排位（Rank 1 ~ 3，未推荐为 0）；
- **声量计算**：根据意图词命中率与推荐排位折算声量可见度（SOV，也就是「品牌在回答里有多显眼」的百分比），沉淀至各项目 `history.db`；
- **异动告警**：当当前 SOV 跌破安全阈值（默认 45%~50%）、环比突降超过 15%、或品牌核心占位词跌出 Top 1 时，系统判定为声量异常；运营仪表盘「声量异常数」与待办行异动标记均消费此结果。

### 3. 就地帮助信息（本轮新增产品要求）
- 凡运营端一眼看不出用途的按钮、徽章、四宫格标题，必须附白话帮助（悬浮 `title` 或旁注小字 / 问号气泡）；
- 帮助文案必须说明「现在是什么意思」和「点了之后会怎样」，禁止内部黑话当主文案。

## Impact (受影响的部分)

- **前端界面**：`web/index.html`（仪表盘 `panel-home-dashboard` 结构与渲染逻辑；运营四宫格、待办行、按钮帮助）；
- **前端状态**：`applyRbacUi()`、`loadProjectsList()`、运营看板聚合（真机台账 + 声量异动）与仪表盘各组件加载器；
- **测试覆盖**：新增/更新 `tests/test_operator_dashboard_perspective.py`，覆盖角色脱敏、四宫格口径、待办行字段与帮助文案存在性；
- **接口安全**：确认 `/api/portfolio/summary` 运营隔离稳固；运营端绝不请求财务大盘接口。
