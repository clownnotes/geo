# Proposal: 商业转化型诊断报告与竞品反哺体系

## Why (为什么做)

当前系统的诊断报告（如 `01_企业AI可见度现状体检与商业诊断报告.md`）偏向**“工程师质检报告”**思维——直接从技术指标（DNS、SSR、robots.txt、代码密度）出发。虽然专业，但传统企业老板看不懂、不敏感，难以将免费体检快速转化为商业订单。

同时，对照实战成熟的 GEO 落地成果（见本目录附带的参考文件）：
1. **报告缺少转化心理旅程**：缺少“先安抚（资产能打不用重做）再暴击（AI根本不认识你，竞品吃你入口）”的心智过山车，缺少“流失的 3 类具体询盘”经济账，缺少“30 天效果前后对照表”和“成交 CTA 钩子”。
2. **竞品分析偏向假算命**：现有的竞品分析偏向哈希推演，未接入真实搜索（WebSearch）；
3. **竞品数据成为孤岛**：竞品只是一张死表格，未反哺给后续阶段（对比类问题无法根据竞品强弱算真实排名和打折）。

**核心解决方向**：
- **两套报告并存（方案 A）**：老板商业转化版与工程师技术体检版**各自成文、整页 Tab 切换**；默认先看老板版；技术版完整保留，不删、不混进同一长页附录。
- **竞品分析真实化**：真实搜索优先，≤5 家同赛道竞品，虚构数据必须标文字 Tag **「虚拟」**（交付报告禁止 Emoji）。
- **竞品反哺闭环**：竞品数据直接反哺可见度模拟与对比类问句。
- **演进铁律**：**一个一个改，分步单测，绝不一锅端**。

## What Changes (改动了什么)

1. **内容能力：转化层 + 技术底座（两套真源，不再混排成一篇）**：
   - **老板商业转化版**（对齐《GEO诊断报告-转化结构大纲.md》）：Hook、一页结论/四维卡、3 类流失询盘、好坏消息、四步破局、30 天愿景、成交 CTA；**不含**生涩技术附录。
   - **工程师技术体检版**：完整保留 Technical Audit 真抓明细、DNS/IPv6、SSR、robots.txt、`/llms.txt`、代码密度、`audit_metrics.json` 真源；供技术验收与留档。
2. **竞品分析真实化（严格对齐《GEO诊断-竞品分析解决方案SOP.md》）**：
   - 采用固定搜索词模板（`{品类} 排名 2026`、`{品牌} 竞品 对比`、`2026 {品类} 市场份额`）；
   - 数量严格限制在 **≤5 家**同赛道、同场景直接竞品，拒绝超大厂滥竽充数；
   - 结构化 11 维字段 Schema（含市占率、威胁等级、优势/劣势等）；
   - 真实数据优先，不足时 AI 推理必须显式标注 `source: "virtual"`，界面/报告用文字 Tag **「虚拟」**（禁止 Emoji）。
3. **竞品数据反哺可见度模拟（闭环联动）**：
   - 竞品 `geoScore` 和 `marketShare` 直接参与“对比类 / 推荐类”问句测算；
   - 强竞品在场时，按知名度等级（头部/腰部/长尾）对客户品牌的推荐率与提及排名进行动态折扣。
4. **增补 30 天愿景对比表与文末成交 CTA 钩子**（写入老板版）：
   - 明确对比 30 天前后的 4 大硬指标（提及率、带官网率、竞品占位、误读风险）；
   - 文末附带克制的单次最低体验价与主理人联系微信。
5. **阶段一顶层双体系（两边都有价值 · 受众与语气不同 · 4 步白盒对称）**：
   - **产品定稿（师弟）——两套报告都要有用，只是写给谁不同**：
     * **老板商业转化版（对客签单）**：基于真抓现实**贩卖焦虑**——先确权资产不用推倒重做，再算 3 类询盘流失账，点明「竞品在吃入口、不做就晚了」，最后给商业破局路线 / 30 天愿景 / CTA（签约语言，不是施工手册）。
     * **工程师技术体检版（给自己施工）**：客观缺陷清单 + **可执行技术改造方案**（SSR、/llms.txt、Schema、文本密度、robots、探测日志）；不卖焦虑、不塞体验价 CTA。
   - **分水岭不是「有没有方案」，而是「方案写给谁、用什么语言」**：
     * 老板版方案 = 商业破局与紧迫感（焦虑→希望→行动）；
     * 工程师版方案 = 问题→怎么改代码/内容底座（内部施工）。
   - **坚决拒绝胡编乱造，第一步必须真截（老板不是傻子）**：
     * 无论哪个 Tab，第一步必须是 **`① 真抓网络与底座指标`**，落盘 `audit_metrics.json`；截图里老板版若只剩「直出骨架」而无真抓，属阶段 8 残留，阶段 9 必须改回两边都先真抓。
   - **两套页面 4 个白盒步骤精准对称**：
     * **工程师技术体检版**：
       - `① 真抓网络与底座指标` ❓
       - `② 直出技术体检与改造方案初稿（程序生成 · 0 幻觉）` ❓（问题清单 + 技术改造步骤）
       - `③ 复制技术指标与改造方案初稿（给 IDE 再审）` ❓
       - `④ 追加豆包问答稿与提示词（给 IDE 参考）` ❓（索引/收录排障）
     * **老板商业转化版**：
       - `① 真抓网络与底座指标` ❓
       - `② 直出商业诊断与焦虑转化初稿（程序生成 · 0 幻觉）` ❓（流失账 + 不做就晚了 + 四步破局/30 天；可选小毛驴反差话术）
       - `③ 复制商业报告与转化初稿（给 IDE 润色）` ❓（商业顾问润色焦虑与签约话术）
       - `④ 追加豆包问答稿与提示词（给 IDE 参考）` ❓（买家心智与竞品截流证据）
   - **消灭操作钮与交付物重复**：卡片内不设「导出 HTML / 复制全文」；统一在交付物右上角。
6. **按钮文案语义直白化（消除黑话 · 阶段 9 定稿名）**：
   - 两边统一 `①`～`④` + `help-circle`（0 Emoji）；
   - 老板②：**`② 直出商业诊断与焦虑转化初稿（程序生成 · 0 幻觉）`**（可副标：含破局路线）；
   - 老板③：**`③ 复制商业报告与转化初稿（给 IDE 润色）`**；
   - 工程师②：**`② 直出技术体检与改造方案初稿（程序生成 · 0 幻觉）`**；
   - 工程师③：**`③ 复制技术指标与改造方案初稿（给 IDE 再审）`**；
   - 两边④统一：**`④ 追加豆包问答稿与提示词（给 IDE 参考）`**。
7. **坚守白盒单步原则（严禁黑盒偷跑多步）**：
   - 彻底摒弃“点一个按钮在后台偷偷跑三步”的伪优化，保证每一步原子化、单步可重试。
8. **小毛驴定位降级为【可选】辅助（非必点）**：
   - 程序根据真抓指标直出的焦虑转化初稿 / 技术改造初稿是 100% 可信底座（0 幻觉）；
   - 小毛驴仅可选丰富老板版反差话术，不影响骨架完整性。
9. **复制给 IDE 提示词体系分流**：
   - 第 ③④ 步：工程师 = 架构师改造提示词；老板 = 商业顾问焦虑转化润色提示词。
10. **规范实施铁律：一个一个改**：
    - 任务清单严格按原子步骤切分，单步编码、单测通过，严禁大杂烩一锅端。

## Capabilities (对外能力)

- `python3 -m tools.geo audit <client_id>`：一次生成两份独立 Markdown（老板商业转化版 + 工程师技术体检版）及对应 HTML。
- `GET /api/projects/{id}/export-audit-html?view=boss|tech`：按视图导出对应客户版 HTML。
- `python3 -m tools.geo competitor_gap <client_id>`：基于真实检索增强与 ≤5 家标准 Schema 生成竞品档案。
- 可见度与问句测算引擎：支持读取竞品数据作为权重因子反哺对比类长问。
