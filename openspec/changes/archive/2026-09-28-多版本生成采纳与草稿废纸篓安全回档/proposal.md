# Proposal: 多版本生成采纳与草稿废纸篓安全回档 (含成套版本流水线与素材库S体系)

## Why (为什么做)
- **痛点一（无法区分新旧生成与草稿打磨动线缺失）**：交付人员在点击“重新抓取底座”后，若文件名固定且缺乏清晰版本号，无法确认是否为新数据；且新生成的派生草稿在采纳前需要可编辑打磨，若直接一刀切置为只读会导致专家无法微调校订。
- **痛点二（废弃草稿堆积与误删系统骨干）**：反复抓取衍生多份无用草稿，需要废纸篓收纳；但若允许随意物理删除，一旦误删流水线依赖的核心骨干（如底座指标、问答素材、商业诊断主报告），下游交付直接断链报错。
- **痛点三（废纸篓无法预览且单行顶栏过于拥挤）**：被删草稿若无法查看内容，用户无法判断是否需要恢复；中栏顶栏单行承载多 Tab 与大量操作按钮，导致严重视觉拥挤。
- **痛点四（重复面条代码、跨阶段污染与存量数据未迁移）**：版本提取、采纳互斥在阶段零与阶段一双份实现，缺乏阶段收窄，共享编辑器硬编码槽位，且老数据无 `slotKey` / 混杂 snake_case，违反 SSOT 原则。
- **痛点五（历史母版死锁无法回滚采纳，且版本割裂驴唇不对马嘴）**：采纳新版后第 1 版被标为“终身留档”并禁用采纳按钮，误点采纳后无法切回母版；阶段零采纳 V2 但实测回答仍是老文件，阶段一出具初稿直接覆盖旧初稿，无法形成 V1/V2/V3 全链路成套套餐。
- **痛点六（文件树视觉混乱与冗余前缀）**：左栏带 `01_`、`02_` 冗余前缀，采纳药丸徽章体积过大遮挡文件名，报告命名长而晦涩。
- **痛点七（阶段二素材库缺少动线与分类，人机混杂）**：素材库只是左侧空文件夹，既无入库动线也无 9 因子提纯入口；素材未分块导致大模型 RAG 检索抓瞎，缺乏故事化案例库与人机两分的干净交付机制。
- **业务价值**：建立“全链路成套版本套餐（V1/V2/V3 联动与分支 V3.1 灵感）”+“素材库独立 S 体系（6 大 RAG 黄金分类与人机两分）”+“极简小绿勾视觉”的完整闭环，让交付体系稳固、灵活且极致好用。

## What Changes (改动了什么)

### 第一阶段（已实现并入库 commit `f2e1daf`）
1. **统一交付物版本采纳模型**：区分客户生效底牌（系统保护不可删）与普通草稿（可删除）。
2. **多版本生成与一键采纳（工序槽位互斥）**：底座重抓派生新版，中栏点击【设为客户采纳】后同槽旧版本退级。
3. **安全软删除与废纸篓收纳**：草稿支持移入废纸篓，左栏底部折叠抽屉汇总并支持一键恢复。
4. **生成时间戳与版本感知**：清晰透出版本标签与时间戳。

### 第二阶段（已完成代码与测试收官）
5. **共享配置与采纳/保存互斥纯函数 (`studioArtifactConfig.js`)**：8 大核心工序槽位字典、阶段收窄、`computeAdoptResult`、`computeSaveResult`。
6. **存量数据无感迁移与硬约束不变式 (`migrateAndNormalizeFiles`)**：自动回填 `slotKey`，驼峰 `isDeleted`，单槽单一 active 收敛。
7. **正交只读与候选工作草稿打磨机制**：生效底牌与新草稿自由编辑，淘汰版本与废纸篓只读。
8. **双重不可删除安全锁与死按钮杜绝**：生效底牌、规范骨干、母版不可删，仅草稿渲染垃圾桶。
9. **废纸篓草稿中栏只读查看与确定性移回**：中栏查看被删草稿，一键恢复移出废纸篓。
10. **中栏顶栏重构为双行独立清爽架构**：操作栏与 Tab 栏分行独立。

### 第三阶段（本次 Grill-Me 迭代增量 · 代码与测试已全量落地）
11. **全链路成套版本套餐（Version Set）与无损回滚**：
    - 解除第 1 版不可采纳死锁：任何版本随时可一键【设为客户采纳】回退生效；误点采纳后切回原版本，全链路自动恢复无需重跑；
    - 阶段零提问清单 (V1) ➔ 阶段 0.2 实测回答 (V1) ➔ 阶段一诊断初稿 (V1) ➔ 阶段一最终交付大屏与文字报告 (V1)，全链路成套联动，互不覆盖。
12. **分支灵感草稿微调优化流转 (如 V3 ➔ V3.1)**：
    - 支持在主版本基础上生成分支草稿 `V3.1`，支持打字编辑与保存；
    - 用户手工挑出亮点合入主版本后，可随时删除分支草稿进废纸篓。
13. **阶段 0.2 实测回答 Q&A 成对规范排版**：
    - 回答文件跟随提问清单版本生成 `豆包实测回答_V${N}.txt`；
    - 内容严格采用【测试题目 + 对应回答】成对排版，杜绝光秃答案。
14. **左侧文件树视觉瘦身与极简小绿勾（展示层瘦身，底层兼容稳固）**：
    - **视觉呈现减负**：左栏列表展示剥离 `01_`、`02_` 等冗长序号前缀与冗余中缀，以极简语义短名呈现（如 `豆包提问清单_V1.txt`、`商业诊断初稿_V1.md`）；
    - **底层数据兼容**：底层物理文件名与工序槽位字典（`CANONICAL_SLOT_DICT`）保持规范映射，确保存量 `localStorage` 无缝兼容；
    - **采纳徽章瘦身**：原冗长药丸徽章瘦身为极简小绿勾与版本标：`✓ V1`。
15. **阶段二素材库独立 S 体系与 6 大 RAG 黄金分类**：
    - 素材库独立抽离，使用 `S` 编号（主版本 S1，分支草稿 S1.1）；
    - **人机两分铁律**：系统组装母盘与外部喂 AI 时**仅读取消费 S 主版本**，草稿分支纯供人工参考对比；
    - 建立 6 大 RAG 黄金分类：
      1. 主体与法定边界（S1）
      2. 产品与价格标准（S2）
      3. 客户画像与痛点场景（S3）
      4. 同行策略与参数对比（按竞品公司聚合为 S4_竞品A）
      5. 真实故事化案例库（以故事标题整理客户真实案例，AI 写文故事背书）
      6. 权威凭据与背书（细分：证书资质 S6.1、标杆合同业绩 S6.2）
    - 全新动线：**【先素材分类提取 ➔ 再成套出具普林斯顿母盘 V1/V2】**。

### 第四阶段（本次真机体验 3 图痛点与素材录入架构 · 规范沉淀）
16. **Tab 标签栏首置插入与超量 6 个智能淘汰**：
    - 新打开或激活的文件 Tab 始终移到**第 1 个**（最左侧），消除视觉寻找成本；
    - 标签页上限 6 个：超量时优先自动关闭最右侧（最老）未修改的 Tab；若 6 个均有修改则弹窗询问保存。
17. **初稿派生分支 V1.1 与 Markdown 保留**：
    - 重复出具初稿时，在当前生效版本上派生微调分支 `V1.1`，供专家并列对比修改；
    - 坚持保留原生 Markdown 结构（标题、列表、表格），符合主流大模型（GPT-4、Claude、DeepSeek、Kimi）的高保真上下文理解，无需人工去语法。
18. **阶段二动线错位纠偏与【一键抓取官网 + 粘贴资料】素材分拣台**：
    - 修复 `Step2App.vue` 传参导致的阶段零动线兜底，恢复阶段二 5 步真实动线；
    - 落地【智能素材分拣台】：支持一键抓取官网正文（经由本地 BeautifulSoup 降噪至 3000 字事实骨架）与手工粘贴客户资料，安全契合本地模型 8K Token (约 8500 汉字) 输入上限，一键提纯分发至 S1~S6 黄金分类。

### 第五阶段：【02 客户素材资产管理库】独立整页化、6大分类结构化资产台与时序拨乱反正（本次 Grill-Me 深度对齐成果）
19. **素材库独立成专职大阶段（02 客户素材资产管理库）**：
    - 彻底废除将素材、母盘、博文三者混杂在同一页面的混乱设计；
    - 当前任务范围收敛：**本次仅集中精力做透【02 客户素材资产管理库】单页**，母盘下沉到后续专职任务，绝不混淆贪多；
    - 归属唯一：整理出的一切素材自然归入当前客户的项目知识库，不产生任何归宿歧义。

### 第六阶段：【真实素材库工作台架构 · 师弟立规】（双场景录入 + 中间可改文字稿 + AI切块审核 + RAG语义聚类去重）
20. **中间文字书写稿与双源进场机制（拒绝空中楼阁，极简真实动线）**：
    - 主体为一块**可自由打字与编辑的中间大文字档（工作台草稿）**；
    - **来源场景一（网址抓取）**：输入一个目标网址 ➔ 点击抓取 ➔ 提取网页有价值正文 ➔ 自动回填至中间文字档 ➔ 醒目标注字数计数器；
    - **来源场景二（人工粘帖）**：直接打开本地文档，复制文字粘贴至中间文字档，自由打字修改；
    - **8500 字硬限与智能提醒**：明确提示用户将字数控制在 8500 字以内；若超过 8500 字则拦截提交并友好提示超限，引导用户删减修饰。
21. **AI 语义切块与人工审核干预闭环（Human-in-the-loop）**：
    - AI 将不超过 8500 字的整篇文字进行深度阅读理解，切出多篇结构化素材片段（如 3~4 篇）；
    - 明确标记每个片段建议归属的黄金分类（S1 主体、S2 价格、S3 痛点、S4 竞品、S5 案例、S6 资质）；
    - **人工终审 4 项大权**：
      1. **预览内容**：点开卡片查看完整正文字文；
      2. **手动修改**：直接在切片卡片内二次编辑文字，修正错别字与废话；
      3. **纠正分类**：下拉菜单一键切换所属分类；
      4. **单项废弃**：点击垃圾桶直接丢弃无价值片段；
      5. **确认入库**：人工满意后一键存入当前客户的素材库。
22. **RAG 语义聚类去重机制（师弟立规 · 拒绝死板标题匹配）**：
    - 真实客户素材无标准化标题，去重必须基于内容正文语义相似度而非死板标题；
    - **RAG 语义召回检索**：切块素材入库前，基于正文词元与语义相似度算法比对库中存量素材（实测中文黄金阈值 0.50）；
    - **去重文件夹/子分组聚类**：将语义相似度高于 0.50 的新老素材归并到同一个“去重对比文件夹/二级子目录”中；
    - **人工一键文案合并**：界面左右并排展示重叠文案，人工核对后将两份文案优势合并为一篇终稿，彻底消除重复与自相矛盾。
23. **母盘 (SSOT) 编译与下游阶段三交钥匙官网消费闭环**：
    - 阶段二定稿推进时，自动基于已审核归类的 S1~S6 黄金素材编译生成高权威母盘，并同步持久化至 `geo_step2_master_text_${clientId}` 与 `geo_step3_master_text_${clientId}`，确保阶段三交钥匙官网能够无缝直接消费。

### 第七阶段：【中栏双行标准头部组件抽象与跨阶段复用 (StudioHeader)】（师弟立规 · 彻底杜绝第一排挤扁变形）
24. **中栏双行标准头组件抽象 (`components/studio/StudioHeader.vue`)**：
    - **第一行（状态与快捷操作栏）**：左侧展示当前文件状态徽章（阶段一生效底牌/草稿，阶段二 S1~S6 分类标签）、字符数统计、生成时间戳；右侧通过 `<slot name="actions">` 挂载各阶段专属操作按钮；
    - **第二行（独立 Tab 标签栏）**：完全独立一行整齐平铺展示打开的文件 Tab（`openTabs`），集成高亮选中、`[废纸篓]` 状态标、未保存黄点以及关闭按钮；
    - **双向无缝复用**：第一页 `StudioEditor.vue` 和第二页 `Step2App.vue` 统一引用 `StudioHeader`，彻底消灭第二页第一排挤扁问题，跨阶段中栏 100% 视觉规范统一 (SSOT)。

## Capabilities (对外能力)
- **成套版本套餐引擎 (Version Package Engine)**：全链路跨阶段成套联动，支持任意版本一键回滚采纳与分支草稿对比。
- **极简文件树与状态呈现 (Minimal File Tree Presentation)**：消除冗余前缀，采用极简 `✓ V1` 小绿勾，视觉清爽。
- **智能 Tab 栈管理器 (Smart Tab Stack Manager)**：首置插入、上限 6 标签自动淘汰未修改文件与脏数据保存确认。
- **双行标准工作台头部组件 (Two-Row StudioHeader Standard)**：抽象公共头部，彻底解决 Tab 与操作按钮挤在第一排的痛点，跨阶段统一视觉标准。
- **真实客户素材资产工作台 (Real Customer Material Studio)**：中间可修改文字档、双源（网址抓取/自由粘帖）进场、8500 字安全提醒、AI 语义切块审核台、RAG 语义聚类去重与人工文案合并器。
