# Spec Delta

## Purpose

规范小毛驴前店工作区与 GEO 后厂工作区之间的职责边界、静态网站托管归属、数据库唯一真相源约束与双仓规则协同机制，防止跨工作区开发导致业务分裂或规则冲突。

## ADDED Requirements

### Requirement: 前店后厂职责边界隔离
小毛驴工作区（`/Users/a1/next核心项目`）SHALL 作为 GEO 业务的唯一前店与数据大管家，承载管理台界面、业务接口、权限校验、本地模型调用与关系型数据库；GEO 工作区（`/Users/a1/代码/GEO`）MUST 仅作为无状态后厂计算车间与客户静态成品输出仓。

#### Scenario: 新增管理端页面或业务状态字段
- **WHEN** 团队需要新增 GEO 管理端页面、SOP 卡点字段或外包代采记账字段
- **THEN** 变更 MUST 仅在小毛驴工作区（Vue 3 前端、Go 后端与数据库迁移）完成，禁止在 GEO 仓库新增管理端界面或业务状态 JSON 文件

#### Scenario: 升级爬虫诊断或静态建站引擎
- **WHEN** 团队需要优化官网诊断规则、大模型采样脚本或静态 HTML 生成模板
- **THEN** 变更 MUST 在 GEO 工作区的 Python 引擎中完成，并通过既定后厂异步任务接口向小毛驴提供服务

### Requirement: 静态官网由 Nginx 直接挂载托管
已生成的客户静态官网（`outputs/site/`、`/llms.txt`、`/robots.txt`、`/sitemap.xml`）MUST 由 Nginx 直接挂载磁盘目录对外提供访问并执行缺尾斜杠 301 重定向，SHALL NOT 经过 GEO Python 服务或小毛驴 Go 后端转发。

#### Scenario: 访客或爬虫访问客户静态官网
- **WHEN** 外部请求访问客户静态官网路径且目录末尾缺少斜杠
- **THEN** Nginx 直接返回 HTTP 301 补齐尾部斜杠并挂载静态 HTML 与爬虫探测文件，不占用业务后端进程

### Requirement: 业务数据与保活状态单一真相源约束
所有客户档案、SOP 步骤进度、外包代采订单、异步任务记录及基本盘保活博文记录 MUST 统一持久化在小毛驴的关系型数据库中，GEO 后厂引擎 SHALL NOT 直接读写业务数据库或自行维护平行状态文件。

#### Scenario: 保活博文发布与健康度判定
- **WHEN** 后厂引擎完成一篇客户博文生成并返回发布时间戳与路径
- **THEN** 小毛驴 Go 后端将博文记录写入数据库，并仅依据数据库记录计算 30 天保活状态；若磁盘文件与数据库不一致则触发告警而非静默覆盖

### Requirement: 双边规则对齐与双仓独立闭环整肃
双边工作区的核心规则文件（`GEO/AGENTS.md` 与小毛驴 `AGENTS.md`、`XiuLan_IDE/RULES.md`、`统一后端-Go/RULES.md`）MUST 优先完成对齐；代码整肃按仓库拆分为独立 OpenSpec 变更各自闭环验收，不保留双轨并行过渡期。

#### Scenario: 执行分步整肃流程
- **WHEN** 团队启动整肃工作
- **THEN** 先由人工过目确认并落盘双边规则文件，随后 GEO 仓独立完成模块盘点、后厂异步接口提纯与旧管理台下线，小毛驴仓通过独立变更完成建库与前店开发
