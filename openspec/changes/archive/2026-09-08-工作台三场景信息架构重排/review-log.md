   - 移出主路径并保留在仪表盘列表层/Boost 边缘，能有效净化交付流，显著降低新用户认知负荷。
3. **第 4 步发稿卡「更多」折叠**：`[同意]`
   - 矩阵分发的核心最高频操作是「生成包」与「一键复制主文」；

**架构与工程落地建议**：
1. 🟢 **DOM 调整与事件监听安全**：
   - `web/index.html` 为单文件原生 JS 架构。迁移按钮至 Boost/Ops 容器时，建议直接调整静态 HTML 模板与 `id`/`class`，避免动态重绘 `innerHTML` 导致原绑定的事件监听器失效。
2. 🟢 **项目上下文与前置依赖保护**：
   - Boost 与 Ops 面板独立于步骤向导，触发部分进阶工具（如 RAG 诊断、护城河博弈）时，需确保有统一的项目上下文检查（未选择项目时弹 Toast 引导，依赖数据不存在时友好提示）。

4. 🟢 **场景切换记忆与过渡**：
