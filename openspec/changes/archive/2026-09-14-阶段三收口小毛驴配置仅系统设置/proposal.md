# Proposal: 阶段三收口小毛驴配置仅系统设置

## Why (为什么做)

当前架构已经定死：**算力统一走小毛驴（Nextdoor）**，模型梯队在小毛驴「接入方专属链」配置；GEO 本机只持有一份机器密钥（`NEXTDOOR_API_KEY`）与回环 Base URL。

但阶段三交付流水线仍把 **「配置 Nextdoor」** 放在主操作区，与「立即检测」、状态 Tag 并列。交付人员容易误以为：

1. 还要自己再配一套 AI / 再选模型；
2. 每次进阶段三都必须先点配置；
3. 「Nextdoor」是第三方产品，而不是自家小毛驴中转。

这与「AI 统一管理」的产品事实冲突，造成歧义与误操作风险（尤其是误改 `.env` 密钥）。

## What Changes (改动了什么)

1. **阶段三主操作区**：移除「配置 Nextdoor」按钮；保留状态 Tag +「立即检测」+ 已有问号说明。
2. **文案**：阶段三使用说明改为「算力走统一小毛驴；此处只显示是否在线。密钥在系统设置由运维维护。」
3. **配置入口收口**：密钥写入仅保留在 **系统设置 / 大模型中枢**（及现有弹窗逻辑可复用，但不在交付步骤露主按钮）。
4. **不改后端契约**：`GET /api/llm/status`、`POST /api/llm/config` 仍保留，供设置页与急救使用；本变更以 UI / SOP 收口为主。

## Capabilities (新增或修改的对外能力)

| 能力 | 变更 |
| :--- | :--- |
| 阶段三交付页 | 只读连通状态 + 强制复测；不再引导写 Key |
| 系统设置 · 大模型中枢 | 唯一推荐的「配置 Nextdoor」入口 |
| SOP-03 / 阶段三说明 | 同步「统一算力、设置页配密钥」口径 |
| 问号帮助词条 | 可补充「配置入口为何不在阶段三」说明（可选） |

## Impact (受影响的部分)

- **前端**：`web/index.html`（阶段三卡片、可能首页设置区文案一致性）
- **文档**：`docs/sop/03-rewrite-sop.md`；可选 `docs/sop/01-audit-sop.md` 交叉引用
- **不改**：`tools/geo/llm.py` 运行时解析、小毛驴专属链、机器密钥格式
- **操作流程**：新交付员不再在阶段三配 Key；运维首次装机或换 Key 走系统设置
- **风险**：旧习惯依赖阶段三按钮的人需知入口搬家；设置页路径必须可发现
