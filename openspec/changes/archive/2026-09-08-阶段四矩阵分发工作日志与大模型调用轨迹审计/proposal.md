# Proposal: 阶段四矩阵分发工作日志与大模型调用轨迹审计

## Why (为什么做)

1. **消除执行黑盒与认知落差**：用户在阶段四点击“一键生成核心矩阵发布包”后，系统在后台执行了多平台内容改写、普林斯顿语料注入与发稿包排版。但目前系统只把最终文件存盘，缺乏详细的执行过程审计，用户无法直观确认：后台究竟调用了大模型还是纯 Python 模板、调用的具体是小毛驴中枢的哪个模型/模式、提示词与原始返回内容是什么、以及整个流程与大模型推理分别耗时多久。
2. **构建企业级交付透明审计闭环**：在 GEO 交付与技术运营场景中，必须提供完整的调用轨迹（Call Trace / Audit Log），便于决策者与工程师排查文案生成质量、确认模型调用链路、复盘耗时瓶颈。
3. **满足高效交互体验**：在阶段四操作栏下方提供轻量化的工作日志状态入口，支持一键打开沉浸式大弹窗查看完整工作日志，并支持按键盘 ESC 键快速关闭，保持操作动线顺畅。

## What Changes (改动了什么)

1. **后端执行轨迹采集与结构化持久化（零侵入解耦）**：
   - 在 `tools/geo/distribute.py` 执行链路中引入结构化审计收集器（Run Ledger），记录：
     - ① 脚本生成了什么内容（产物文件名、物理路径、文件大小字节数、字数、发稿包状态）；
     - ② 脚本运行用了多久（整个阶段总耗时 `total_duration_ms`）；
     - ③ 请求模型用了多久（每个渠道 LLM 推理耗时及模型总耗时）；
     - ④ 请求的是小毛驴的哪个模型（调用中枢 `NEXTDOOR_BASE_URL`、端点 `/api/v1/xiulan/chat`、模式 `mode: flash`、客户端标识 `brand: geo`）；
     - ⑤ 请求时的提示词是什么（包含 System Prompt 与完整 User Prompt）；
     - ⑥ 输出结果是什么（大模型原始返回文本 raw_output 与最终存盘文件片段）；
   - 产物写入独立的 `projects/{project_id}/outputs/distribute_run_log.json`，采用 `try...except` 容错隔离，确保日志落盘逻辑即使发生异常也绝不阻塞业务主流程。
2. **新增独立日志读取接口**：
   - 在 `tools/geo/server.py` 中提供只读端点 `GET /api/projects/{id}/distribute/latest-log`，返回最新一次运行的完整结构化明细；若未运行则返回空态标识。
3. **前端界面呈现与沉浸式弹窗交互**：
   - **外露状态指示条（红框区域）**：在阶段四标题卡片下方、3步走引导上方，新增高质感“最新工作日志”状态条，未运行时显示灰色低调提示，运行完成后显示运行摘要（总耗时、调用模型、产物数量与“查看工作日志详情”按钮）；
   - **大弹窗审计查看器**：点击“查看工作日志详情”后，弹出结构化日志查看模态窗口，包含三个核心区块：
     - 总体运行概览卡（脚本总耗时、模型耗时及占比、模型中枢路由信息）；
     - 生成产物清单（文件列表、字符数、文件大小与发稿包状态）；
     - 大模型调用详情明细（按头条、知乎等渠道分别展示提示词 Prompt、模型原始响应 Output、单次耗时与一键复制按钮）；
   - **ESC 快捷键与多维退出机制**：弹窗打开时监听全局键盘事件，按下 `ESC` 键立即平滑关闭；同时支持点击右上角关闭按钮或点击遮罩层退出。

## Capabilities (新增或修改的对外能力)

1. **数据模型 `distribute_run_log.json`**：标准化记录阶段四单次完整执行生命周期与 LLM 调用审计；
2. **API 端点 `GET /api/projects/{id}/distribute/latest-log`**：查询指定项目的阶段四最新执行审计日志；
3. **前端工作日志状态条与 Modal 查看器**：支持 ESC 键关闭、支持提示词与输出一键复制。

## Impact (受影响的部分)

- **核心代码**：
  - `tools/geo/distribute.py`：注入执行计时与 LLM 上下文审计收集；
  - `tools/geo/server.py`：新增 `/api/projects/{id}/distribute/latest-log` 路由；
  - `web/index.html`：在阶段四 DOM 结构中注入日志指示条与模态弹窗，添加相关 JS 交互函数（`loadDistributeRunLog`、`openDistributeLogModal`、`closeDistributeLogModal` 及 `keydown` ESC 监听）。
- **架构耦合度评估**：
  - **零耦合**：采用旁路（Out-of-band）独立文件落盘与独立读取 API，不侵入核心发稿包逻辑，不改变既有 API 响应协议；
  - **故障隔离**：日志收集出现任何异常均不打断分发流程；
  - **测试兼容**：现有 14/14 单元测试不受任何影响。
