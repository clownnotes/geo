# Proposal: 阶段零出题落盘与冒烟护栏

## Why (为什么做)

- 产品反复遇到「Cursor/IDE 在对话框总结了题，管理台像没读到」——根因多半是**只聊未落盘**（先聊后盘等人口令），不是磁盘丢了；界面又没说清，安全感极差。
- 阶段零改代码翻车比例偏高（大单页半截改坏、字段对不上、假「加载中」）。组件岛已拆出，但仍缺**改完必跑的冒烟护栏**，否则还会反复误判成「又丢数据」。
- 需要同时堵两条缝：**流程上题必须进磁盘可见**；**工程上改完能自动验关键路径**。

## What Changes (改动了什么)

1. **出题落盘契约**  
   - 保留「先对话框列题给人改」；但增加明确出口：人说「可以落盘」/「直接落盘」→ 必须写入 `probe_script_*.json`。  
   - 可选强化：列题后若迟迟不落盘，管理台/提示词侧要能提示「聊天里可能有未落盘拟问」，避免当成读失败。  
   - 落盘文件命名约定（如复测 `probe_script_retest_roundN.json`）写死，刷新后 B 区必能看见。

2. **管理台人话状态**  
   - B 区区分：空列表（真没有文件）vs 有旧文件但「本轮拟问尚未落盘」（流程未完成）。  
   - 禁止用「清单加载中」永久卡住；失败必须人话报错。

3. **冒烟护栏（最小可自动化）**  
   - 脚本或 npm 任务：`build:step0` → 检查产物存在 → curl `/assets/step0/step0.js` 非 404 →（可选）断言 guide 有 scripts 时前端状态机不为永久 loading。  
   - 约定：改阶段零代码后**未跑冒烟不得宣称完成**。

## Capabilities (新增或修改的对外能力)

- IDE 出题链路：列题 →（确认）→ 落盘 → 管理台可见，闭环可核对。  
- 管理台：对「未落盘」有白话提示，降低假丢数据恐慌。  
- 工程：阶段零一键冒烟，降低改代码回归率。

## Impact (受影响的部分)

| 影响面 | 说明 |
| :--- | :--- |
| `web/step0-src/` / `plainCopy` 提示词 | 落盘口令与未落盘提示文案 |
| 管理台 B 区 | 空态/未落盘态文案（不改磁盘契约则可不改 API） |
| `package.json` / `scripts/` | 新增 `smoke:step0` 或等价 |
| `tools/geo/server.py` | 冒烟依赖现有 `/assets/`；一般不改 |
| 非目标 | 全站测试框架大升级；改豆包实战 API；推生产 |

## 与前序变更关系

- `管理台阶段零Vue3组件岛` 已归档；本变更在组件岛之上补**流程与护栏**，不重做整岛。
