# Proposal: 发前对照卡 Git 式逐条确认

## Why (为什么做)

阶段三「发前对照」当前心智分裂：

1. **对照卡在长预览下方**（或虽已上移仍不够直观），用户看完差量后却被引导去「唯一真相源」用「历史确认 / 候选 / 当前」三选一 +「仲裁」——像填表格，不像改稿。
2. 产品真实决策只有两态：**过去（钉住基线） vs 现在（当前真相）**。三选项下拉（尤其「历史候选」）难懂、易选错。
3. 期望流程是 Git 找不同：刷新对照 → 看原先/现在 → 新增绿、删除灰 → **打勾固定** → 全部确认后再钉住母盘。

## What Changes (改动了什么)

1. **刷新对照**：稳定展示「原先是什么 → 变成了什么」（相对 pinned 基线）。
2. **视觉**：新增绿色、删除灰色；变更同时展示旧（划线）与新。
3. **逐条动作**：每条仅 **✓ 打勾固定**（采用当前展示的「现在」结果；删除行打勾=确认删除）。可选保留 ✗ 作为「恢复原先」，但主路径是打勾固定。
4. **去掉对照卡对「历史候选下拉」的依赖**：拍板不在真相源三选一完成。
5. **唯一真相源**：面板不大改；有未决冲突/与钉住版不一致时，用轻量提醒（角标/旁注）即可，不强迫在列表里做 diff。
6. **钉住前置**：「全部确认」汇总本轮对照拍板 → 成功后再允许 / 引导「钉住当前母盘」。

## Capabilities (新增或修改的对外能力)

| 能力 | 变更 |
| :--- | :--- |
| 发前对照卡 | Git 式差量 + 逐条打勾固定 |
| 全部确认 | 对照区一键收口本轮决策，作为钉住前闸门 |
| 钉住母盘 | 仅在全部确认通过（无未决硬冲突）后执行 |
| 唯一真相源 | 仅提醒「有变动/有冲突」，不做主决策 UI |
| API | 固化/收口 `corpus/diff`、`corpus/diff-decide`、（可选）`corpus/diff-confirm-all` |

## Impact (受影响的部分)

- **前端**：`web/index.html` 发前对照卡、钉住按钮态、真相源旁注
- **后端**：`tools/geo/corpus.py`、`ledger.py`、`server.py`；已有实验性 `diff-decide` 需按本 Spec 对齐语义
- **文档**：`docs/sop/03-rewrite-sop.md` 发前对照步骤
- **测试**：`tests/test_corpus_incremental.py`
- **不改**：小毛驴密钥入口（已归档收口）；阶段四矩阵逻辑本身
- **风险**：旧习惯「去真相源仲裁」需文案迁移；「全部确认」与单条打勾的幂等要清晰
