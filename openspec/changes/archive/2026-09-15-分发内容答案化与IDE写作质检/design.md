# Design: 首次交付 · 路牌管理台 + IDE 工地

## 1. 产品心智

```
管理台第四页   = 路牌（SOP 下一步提醒 + 一键复制口令）
机器生成       = 草稿（半成品）
IDE + 人       = 工地（讨论、改稿；满意后再落盘）
写回口令       = 告诉 IDE：正文写入哪条路径（留档）
「可以发」勾选  = 放行确认（不是写作工具）
复制富文本     = 只对已放行的定稿文件
```

**明确不做**：管理台内嵌长文编辑器；管理台大粘贴框「在线填稿」。

---

## 2. 第四页信息架构（垂直顺序硬约束）

### ① 生成草稿

- 主按钮：`生成草稿`；状态：`仅草稿`

### ② 段 A · 说明书（只读）

- 主问句、用途、模具、可写事实、写回路径展示  
- **不得放**「可以发」或发布复制

### ③ 段 B · 怎么定稿（路牌 + 两个复制出口）

- 主按钮：`复制给 IDE 改写`（开工）  
- 次按钮：`复制写回口令`（满意后落盘；可与改写同级醒目，勿藏「更多」）  
- 旁注四步：  
  1. 复制改写包  
  2. 在 IDE 改到满意（可反复讨论，不必立刻写文件）  
  3. 复制写回口令 → 贴回 IDE → 写入规定路径  
  4. 回本页勾「可以发」  
- 旁注金句：`本页只指路。定稿在 IDE 写；满意后点「复制写回口令」让 AI 写入规定文件；再回来勾「可以发」。勾选不会改文章。`  
- 渠道卡（头条必做 / 知乎加分）放本段

### ④ 段 C · 发布前确认（必须在段 B 之后）

- 账号 + `定稿已写好，可以发（放行确认）`  
- `复制富文本去头条/知乎`  
- 直达后台；回填探活

---

## 3. 数据契约

### 3.1 改写包（开工）

字段：主问句、用途、模具、可写事实、禁止项、写回路径、当前草稿、落盘提醒（可先聊后落）。

### 3.2 写回口令（落盘）

| 字段 | 说明 |
| :--- | :--- |
| 标题 | `【GEO 阶段四 · 写回定稿】` |
| project_id / channel | 对号 |
| writeback_path | 与发布同源 |
| instructions | 覆盖写入；HTML/约定格式；0 Emoji；回报路径与字数 |
| body_slot | 粘贴满意正文，或「用本对话已定稿最后一版」 |

API 建议：`GET /api/projects/{id}/answer-rewrite/writeback-cmd?channel=toutiao`  
返回 `{ clipboard, writeback_path, channel }`。

### 3.3 发布复制

优先读 pack 已写回文件；禁止默默 `build_*` 盖掉定稿。

## 5. 质检

定稿写回之后、复制发布之前；本阶段人工「可以发」；自动质检后置。
