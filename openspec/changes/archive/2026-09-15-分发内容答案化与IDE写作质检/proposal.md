# Proposal: 分发内容答案化与 IDE 写作质检

## Why (为什么做)

第四页旧逻辑是「生成 → 复制发出 → 回填」。  
实测问题：

1. 一键生成常是软广/简介体，不能当豆包答案源。  
2. 「保真度 100」≠ 可以发。  
3. 质检曾审错文件（审 Markdown，发布却复制另一份富文本）。  
4. 草稿按钮与发稿按钮语义混在一起，诱导「生成完就粘头条」。  
5. 人不知道「定稿写完后怎么填回电脑」——缺一条可复制的写回口令。

产品共识（2026-09-15 续）：**管理台 = 路牌**；**IDE = 工地**；可先在 IDE 讨论，满意后再用写回口令落盘；不做管理台填稿框。

## What Changes (改动了什么)

1. **规范**：工作流含「写回口令」；明确前端只指路、干活在 IDE。  
2. **第四页垂直顺序**：说明书 → IDE（改写包 + 写回口令）→ 发布前确认。  
3. **IDE 改写包** + **写回口令**两套剪贴板。  
4. **发布源与写回路径同源**（优先 pack 富文本）。  
5. **质检自动化后置**；人工「可以发」即可。  
6. **首次不做**管理台内嵌编辑器 / 大粘贴框。

## Capabilities

| 能力 | 说明 |
| :--- | :--- |
| 答案源写作规范 | 模具、禁止项、改写包、写回口令 |
| 首次交付 SOP-04 | 路牌 vs 工地；草稿≠定稿≠可发 |
| 第四页 UI | 改写 / 写回口令 / 发布三分离 |
| 可发确认 | 人工勾选 |
