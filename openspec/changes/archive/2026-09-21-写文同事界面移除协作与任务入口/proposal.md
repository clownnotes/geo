# Proposal: 写文同事界面移除协作与任务入口

## Why (为什么做)
1. **写文同事需要极简纯粹的界面**：写文同事的核心任务是给企业客户创作高质量文章并交付，不需要接触程序员的后台调试工具。
2. **「协作与任务」对写文同事是认知噪音**：该模块充满 `audit`、`scaffold`、`probe` 等英文命令行参数和终端黑框日志，与日常写文主流程严重脱节，容易造成误操作和困惑。
3. **彻底收敛非写文入口**：贯彻面向对象思维，将「协作与任务」定位为“开发者专属后台运维监控台”，从写文同事的操作界面中彻底移除，仅保留给开发者。

---

## What Changes (改动了什么)
1. **工作台侧边栏隐藏入口**：
   - 在 `web/index.html` 中，为侧边栏的「协作与任务」导航项（`#nav-home-collab`）添加 `data-geo-dev-only` 标记，写文同事登录后侧栏不再显示该项。
2. **路由视图跳转硬防护**：
   - 在 `web/index.html` 的 `switchHomeView` 守卫中将 `'home-collab'` 放入 `devOnlyViews`。`showDashboard()` 里还有一份同样的名单（约 6235 行），两处都要加，否则刷新旧地址仍能进。禁止给 `#panel-home-collab` 加 `data-geo-dev-only`。
3. **测试回归与断言对齐**：
   - 编写或更新自动化测试脚本，验证写文同事身份下侧边栏没有「协作与任务」，且切到该视图会被安全拦截回仪表盘。

---

## Capabilities (新增或修改的对外能力)
- **写文同事极致纯粹工作台**：写文同事的侧边栏只保留最核心的「仪表盘」与「企业管理」，视线中无任何无关杂物。
- **开发者运维能力完整保留**：开发者登录后依然能正常访问「协作与任务」，后台排队互斥、实时日志和打包下载能力完全不受影响。

---

## Impact (受影响的部分)
1. **前端界面**：`web/index.html`（侧边栏 DOM 属性与 `switchHomeView` 权限逻辑）。
2. **测试脚本**：`tests/` 下相关 RBAC / 权限 UI 测试。
3. **底层能力**：后端 `task_runner.py` 与 API 保持不变，开发者与系统底层调度无影响。
