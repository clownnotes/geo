# Proposal: 全流水线主文件建档预置与参考比对候选件(1/2/3)双轨清晰架构

> 📌 **【文件结构与审核总纲声明】**：
> 本文件由「第一部分：AI 整理方案」与「第二部分：用户原话实录」两部分组成：
> 1. **第一部分（正文）**：由第一个 AI 整理的技术方案，**仅供参考，绝对不能当成既定事实**；
> 2. **第二部分（文末）**：由系统底层物理抓取的用户真实发言，**是最高第一真理源**。
>
> ⚖️ **【致外部审核 AI（Reviewer）的最高铁律】**：
> 审核时你必须**亲自独立阅读并理解第二部分的用户原话**！**完全不要相信第一个 AI 总结的内容**（第一个 AI 的总结只能作为参考）！
> 你必须用自己的大脑去对照核验：第一个 AI 的方案是否真正面向用户的业务场景解决了问题、是否在偷换概念掩耳盗铃、是否在打补丁！



## 1. 痛点背景 (Why)
- **版本规则冲突与割裂**：
  此前各工序版本逻辑不统一：阶段零历史曾采用 `V1、V2、V3` 成对大版本模式；阶段二采用素材切块增补模式；阶段三又是母盘合流模式。这种混杂导致认知混乱，甚至出现“第一版绑定第一版，第二版绑定第二版，同时又派生 1.1/1.2 往第一版合”的逻辑冲突。
- **空白界面的空城计恐慌**：
  如果新项目创建时是空的、非要等到用户点生成才掉落文件，会导致交付人员进页面看到白板、不知道下一步做什么，且后端下游检查极易因为文件不存在而触发各种门禁死锁报错。

## 2. 核心共识方向 (What)
1. **全流水线各阶段交付物统一模型：【主文件 + 参考比对候选件(1/2/3)】体系**：
   - 每个槽位有且仅有 1 个【主文件】（右侧晨光淡黄打勾），终身不可删除，可随时自由编辑保存；
   - 重新生成的内容统一作为【参考件】（统一由系统自动追加编号 _参考1、_参考2，不支持人工重命名，仅供比对与删除），专供人工对比与更新主文件，严禁一键整篇覆盖主文件；
   - 门禁质检（5 点核心检查法）与下游所有消费 100% 只读【主文件】。
2. **阶段二素材库定位澄清**：
   - S1~S6 是权威主版本；增量上传切块属于“增补分片池”（供 RAG 向量检索，不属于工序交付主版本）。
3. **采用【建档即预置主文件底盘，后续生成逐步丰富】模式**：
   - 项目一经创建，系统立即根据建档四要素（品牌、主体、官网、行业）自动预置全套主文件；
   - 用户后续点击生成、切块或回填，产生参考件或直接增量合并进主文件，彻底消除空白等待。

4. **主文件标识纯净统一为右侧晨光淡黄对勾 `✓`（彻底清除 V1 / QA-V1 混杂）**：
   - 消除各工序、各阶段标签不一的认知负担，主文件仅在文件名右侧展示类似“晨光破晓”暖金淡黄色的对勾 `✓`，温润高级且一目了然。
5. **主文件支持人工自定义重命名，底层以不可变雪花 ID / slotKey 为寻址锚点**：
   - 消除机器生成生硬抽象命名的痛点，允许交付专家自由重命名（如改叫“徐州老赵五问豆包.txt”）；
   - 每个主文件分配唯一的雪花 ID 编号，底层槽位与下游门禁全部通过雪花 ID 寻址，改名绝不破坏依赖。
6. **文件树拿掉左侧无用文件图标，释放空间看全文件名**：
   - 树里 100% 都是文件，拿掉左侧千篇一律的小图标，把整行宽度都留给文本，字更大更清晰。
7. **界面彻底隐藏扩展名与电脑桌面级右键改名**：
   - 界面一律不向交付人员暴露 `.txt`、`.md` 等技术扩展名，统一展示干净的主名称；
   - 交互上完全对齐 macOS / Windows 桌面体验，支持在文件项上右键唤起【修改名称】，就地行内改名回车存盘。

## 3. 对外能力表现 (Capabilities)
- `cap-preset-master`：建档即预置全套工序主文件底牌，彻底告别白板；
- `cap-master-warm-check`：主文件右侧展示晨光淡黄对勾 `✓`，纯净高辨识度，彻底剔除 V1 等多余字符；
- `cap-tree-space-optimization`：取消文件左侧小图标，横向空间全量释放给文件名展示；
- `cap-master-rename-snowflake`：主文件支持人工自由重命名，底层绑定雪花 ID 唯一锚点；
- `cap-hide-extension`：界面全域隐藏 `.txt` / `.md` 等技术扩展名，呈现纯粹文件名；
- `cap-context-menu-rename`：桌面级右键菜单唤起【修改名称】，行内平滑重命名并按回车即时更新；
- `cap-dual-pane-ref`：支持左右双栏比对或参考模式，右侧/Tab展示重新生成的参考候选件（1/2/3），主文件人工挑词更新；
- `cap-master-protection`：主文件强物理防删，禁止整篇覆盖冲毁，确保人工精修安全；
- `cap-single-master-gate`：下游门禁与流水线统一只检查主文件的 5 点就绪状态；
- `cap-distill-sheet`：网页/文案蒸馏大盖板工作台，抽屉式极简交互与纯文本清洗；
- `cap-semantic-chunk`：AI 语义切块与 8500 字上限管控，自动归集 S1~S6 素材；
- `cap-identity-card`：阶段三主体信息统一口径卡生成、四要素消歧与三级业务描述字数红绿灯（含逐平台打扫卫生操作指引）；
- `cap-princeton-master`：六模块企业事实母盘合流萃取（定位/产品/客户/差异/案例/背书，供人类查证字典，严禁喂AI）；
- `cap-stage3-sop-revamp`：阶段三全面对齐老赵哥正统实战 SOP，废除孤立 03 号碎片文件，右侧 SOP 采用老赵哥实战大白话 4 步指导；
- `cap-official-url`：官网网址唯一真相源、去除重复协议与域名提取；
- `cap-pure-trash-readonly`：除废纸篓外彻底解绑生硬只读限制，全域文件自由输入打磨，主文件作为唯一权威消费源；
- `cap-zero-lock-navigation`：彻底废止流程锁与切换弹窗，00~07 全工序平滑自由穿梭，以主文件事实为唯一就绪真相；
- `cap-stage-resequence-matrix`：00~07 全流水线工序顺延与映射矩阵，新增阶段七验收结案并保持 LEGACY_VIEW_REDIRECT_MAP 双向兼容；
- `cap-pure-source-collaboration`：纯前后端业务源码（现为 `src/` 三块 + `tests/`）白名单物理导出与协作者独占工作仓，战略、规范、运维脚本与服务器坐标 100% 物理隔离；
- `cap-oneway-delivery-and-reflow`：**单向下行**出包（含清洗与清单）+ 同事 PR 合入后由 AI 按 `delivery-manifest.json` 两方比对回灌主仓；**已按 2026-10-08 裁决废除“双向同步 / 拉取合流脚本”旧口径**，主仓永不添加同事 remote。

## 4. 影响范围 (Impact)
- 全流水线 0~7 阶段工序面板的主文件预置、重命名与参考比对件生成策略；
- 阶段零、一、三、四~七的统一主文件与参考比对件交互；
- 全流水线 8 步工序顺延（00 侦察、01 报告、02 素材、03 母盘、04 官网、05 答题卡、06 分发、07 验收）及旧 viewId 自动正规化重定向；
- 全流水线 5 点核心质检指示灯与门禁检查；
- 扩展自动化冒烟断言至 32 项全部 PASS，保障全流水线数据与架构稳健闭环；
- 大幅简化文件树渲染、降低交付人员上手认知负担；
- 仅新增**单向**出包脚本（重写 2026-10-07 的旧导出脚本，旧的“协作拉取合流脚本”口径已废除），主仓 `src/`、`tests/` 在出包过程中保持只读，不影响任何已有运行与部署链路；同事仓 `GEOChen` 为同事独占写区与我方只读参考镜像。
