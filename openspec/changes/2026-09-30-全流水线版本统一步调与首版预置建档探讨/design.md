1. **战略保密与纯源码隔离**：“我的战略文档里还有一些乱七八糟的内容，还有我的规范，我并不希望都公开出去，而且公开出去对别人来说也不是很方便，只需要源码。那这种情况下，我是不是能够再建一个远程仓库？这个远程仓库只推源码？对方提 PR 我这边合并？”

5. **零预设与协作者自由折腾立规**：“他只要前后端源码 其他的他自己弄 里面的文件夹他也会自己去弄 这个文件夹就是单独弄出一个远程仓库 给朋友去折腾的 然后我们拿着文件夹 来和合并的的时候，能看懂就好了。”

7. **严禁并列文件夹与幻觉架构**：“你这他妈叫什么优雅的方法 我搞了半天 我要早知道你这么干 这不是神经病吗 我天那。那以后写代码不是各种幻觉？怎么分清哪里是哪里？这他妈不是有病么？”

9. **源码内聚与一级目录清爽立规**：“你就先把我们自己 geo 这里改造一下 把源码放在源码文件夹里，不要都铺开在一级菜单里。”
10. **源码与脚本按需归位立规**：“这个脚本跟源码有关系吗？脚本不是我们本地测试用的吗？源码能不能用到？如果源码能用到，就放到源码里面。也就是说，这个脚本跟这个项目有没有关系啊？如果有关系，那就放到项目里；如果没关系，就不要放到项目里。这不是很清晰吗？”

## 1. 核心架构模型：主文件 + 参考生成文件体系 (Master-Reference Model)

### 1.1 对象两分与生命周期铁律
全流水线各阶段交付物彻底废除复杂的小数点（1.1/1.2）切片逻辑，统一收敛为清晰的“主参考两分法”：

```text
【主文件 (Master File)】—— 槽位唯一、晨光淡黄对勾 `✓`、不可删除、可编辑保存（全流水线下游 100% 消费源）
  ├── 00 阶段：01_豆包提问清单_推荐版.txt  &  02_豆包实测回答记录_初测.txt  [主文件]
  ├── 01 阶段：01_商业体检报告.md  [主文件]
  ├── 02 阶段：S1~S6 核心企业资产主版本 (S1~S6 各1个)  [主文件]
  └── 03 阶段：01_主体信息统一口径卡.md  &  02_普林斯顿企业事实母盘.md  [主文件]
        │
        ▲ (人工双栏比对 / 挑词吸收 / 手工提纯更新，禁止一键整篇覆盖)
        │
【重新生成的参考文件 (Reference / Drafts)】—— 统一由系统自管编号（_参考1, _参考2...），自由增删
  ├── 01_豆包提问清单_参考1.txt
```

### 1.3 交互动线：双栏比对与人工提纯更新 (Dual-Pane Comparison)
- **禁止一键整篇覆盖**：彻底废除“一键采纳整篇覆盖主文件”机制，主文件内容受物理防冲毁保护；
- **左右双栏工作台布局**：
  - **左栏【主文件工作区】**：展示当前受保护的唯一【主文件】，支持自由编辑、实时保存、5 点指标质检；
  - **右栏【参考灵感池】**：展示选中的重新生成版本（如 `_参考1`、`_参考2` 等）；
  - **人工挑词与提纯**：交付人员在右栏阅读 AI 生成的参考版本，人工复制优秀题目或素材段落，粘贴进左栏主文件中融合；
  - **参考件生命周期**：参考件参考完毕后，交付人员可随时删除清理，绝不污染主干。

### 1.4 界面空间极致瘦身与主文件晨光淡黄对勾架构 (`cap-master-warm-check` & `cap-tree-space-optimization`)
1. **彻底取消文件左侧小图标（空间极致释放）**：
   - 树里 100% 都是文件，拿掉千篇一律的 `file-text` 废图标，彻底解决长文件名被省略截断问题；
   - 释放出来的宽度全部留给真实文字，文字字号更饱满清晰，一目了然看清更多文件。
2. **主文件右侧晨光淡黄对勾 `✓`（去 V1 与文字噪点）**：
   - 彻底废除 `生效版本 QA-V1`、`客户生效底牌 V1` 及冗长文字徽章；
   - 主文件仅在文件名**右侧展示一个温暖醒目的【淡黄色对勾 `✓`】**（晨光破晓小手小毛驴暖黄配色，坚决不用刺眼绿色）；
   - 参考件右侧展示垃圾桶删除图标，主文件右侧绝不出现删除图标，一眼辨明主次。
3. **文件名人工修改与雪花 ID 唯一锚点**：
   - **痛点根本解**：电脑机器预置的名字过于抽象（如 `01_豆包提问清单_推荐版.txt`），交付人员需要能够自由修改为亲切具体的名称（如 `徐州老赵五问豆包.txt`）；
   - **数据结构与锚点绑定（StudioFile 完整数据模型 · 解决 R-2）**：
     ```typescript
     interface StudioFile {
       id: string;                 // 雪花 ID 唯一编号 (不可变字符串，如 "197364819283748291")
     ```

   - **雪花 ID 生成算法与精度铁律（解决 R-3）**：
     - `generateSnowflakeId()` 必须在 `studioArtifactConfig.js` 纯函数层统一定义与导出；
     - 全程使用 `BigInt` 运算并输出为纯 `string`，严禁使用 32 位位运算截断；
     - 结构组成：41 位时间戳差值 + 10 位机器节点 (默认 1) + 12 位自增序列号，单毫秒溢出或时钟回拨时采用防倒退自增机制；
     - **多标签页并发防碰撞（考官 Y6 补）**：同一浏览器开两个标签页在同一毫秒各自建文件时，序列号都从 0 起会撞号；故 10 位节点段改为**每标签页随机 workerId**（首次生成时随机、之后在该标签页内固定，可选用 `sessionStorage` 持久化），并保留 `localStorage` 记录 `lastTs + seq` 作为兜底；若为此新增冒烟断言，必须同步更新全仓写死的“32 项”计数口径（见 §7.6 与 tasks 10.4）。
   - **寻址与依赖解耦**：
     下游工序、门禁检查（5点质检）全部通过 `getMasterFileForSlot(files, slotKey)` 或直接基于 `id` 寻址；
     文件名的修改仅作用于展示层 `displayName`，底层雪花 ID 和槽位终身不变，实现“改名自由 + 底层 100% 稳定”。

   - **仅主文件开放重命名**：只有唯一主文件支持右键修改名称；
   - **参考件系统自管**：重新生成的参考候选件统一由系统自动追加编号（如“参考1”、“参考2”），仅供临时对比参考与删除，不支持重命名，彻底杜绝多版本命名混乱。
7. **改名重名强拦截防呆**：
   - 若交付人员输入的新名字与同列表内现有文件重名，系统立即轻提示“名称已存在”，阻断保存并自动恢复原名，严禁同名撞车。
8. **只读权限彻底解绑（仅废纸篓只读，全域自由打字编辑）(`cap-pure-trash-readonly`)**：
   - **痛点根本解**：旧设计对历史母版、规范骨干镜像、淘汰草稿强加只读锁（显示禁止光标），导致交付人员在参考文件或辅助文件里想微调两句话直接被锁死，体验极其生硬恼人；
   - **铁律确立**：全系统【除移入废纸篓（isDeleted === true）的文件强制只读外】，所有主文件、参考件、草稿、历史归档全部彻底解绑只读限制，允许随时自由输入、编辑打磨与存盘；
   - **安全屏障**：下游工序与 5 点门禁 100% 仅认带暖黄对勾的【主文件】，交付人员对非主文件的打磨编辑完全安全隔离，永不破坏主干。
9. **主文件判定唯一真相源 (SSOT) 与彻底清除历史归档干涉（解决 R-1）**：
   - **痛点根本解**：此前改名报错“参考件由系统自管编号，仅主文件支持修改名称”，根源是存量迁移函数根据 `_第1版` 后缀将旧生效主文件错误打上 `isProtectedArchive: true` 标记，导致 `isMasterFile` 在排除历史归档时一票否决；同时文件树与改名拦截判定标准不一致；
   - **唯一判定铁律 (SSOT 纯函数定义)**：全仓统一使用 `isMasterFile(file)` 纯函数判定，口径完全等价：
     ```javascript
     export function isMasterFile(file) {
       if (!file) return false;
       if (file.isDeleted || file.is_deleted) return false;
       if (file.isReference === true || String(file.versionTag || '').startsWith('参考') || (file.name && file.name.includes('_参考'))) {
         return false;
       }
       if (file.isMaster === true) return true;
       if (file.isActive === true && !file.isManual && file.slotKey !== 'slot_manual' && file.slotKey !== 'slot_misc') {
         return true;
       }
       const allCanonicalNames = Object.values(CANONICAL_SLOT_DICT).map((item) => item.canonicalName);
       if (allCanonicalNames.includes(file.name) && file.isActive !== false) {
         return true;
       }
       return false;
     }
     ```
   - 彻底废除 `_第1版` 强制打 `isProtectedArchive` 的陈旧规则，严禁任何历史留档标记覆盖或冲毁当前生效主文件的改名权限；
   - `StudioFileTree.vue` 的打勾展示、右键菜单开放与 `handleRenameFile` 改名拦截 100% 统一调用 `isMasterFile()`。

## 6. 老赵哥正统 GEO 全链路实战 SOP 全景沉淀 (Permanent Domain Truth)

### 6.1 一句话说透 GEO 的本质与大模型运行机制
- **GEO 的本质**：让“关于你的正确事实”，尽可能多地出现在大模型（豆包、DeepSeek、Kimi 等）会采信的地方；
- **大模型怎么认识企业**：大模型不是神仙，它靠抓取全网公开数据（工商年报、天眼查、爱企查、高德地图、BOSS直聘等）进行概率推理和交叉验证；
- **致命硬伤（信息打架）**：若企业在天眼查写做返利网、启信宝写做支付服务商、BOSS直聘写几百人但年报写 0 人，AI 抓取后就会直接判定为“信息自相矛盾、涉嫌虚假招商、皮包公司”，外部花再多钱发文章也会被底层脏数据瞬间一票否决。

### 6.2 12 步流水线全景流转地图 (S0 ~ S11)
```text

```

1. **S0 开工收资料**：收齐执照、官网、产品手册、客户案例、资质证书等原始材料。巧妇难为无米之炊，所有内容必须由此提纯，严禁胡编；
