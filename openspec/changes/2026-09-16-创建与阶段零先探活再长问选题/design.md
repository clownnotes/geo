# Design: 创建与阶段零先探活再长问选题

> **本文件是本变更的规范真源。** 勿再散落 `docs/specs/*` 旁路。  
> 变更目录：`openspec/changes/2026-09-16-创建与阶段零先探活再长问选题/`

---

## A. 名词（相对前序归档的修正）

| 名字 | 是什么 | 不是什么 |
| :--- | :--- | :--- |
| **母盘** | 企业定位与已确认口径 | 某一篇稿 |
| **选题（长问）** | 真人会问的完整问句；写/发/复测/客户确认的对象 | 短标签如「徐州GEO」 |
| **文章** | 按母盘、围着某条选题写的定稿 | 拿短词当标题硬写 |
| **探活基线** | 阶段零问豆包得到的认知体检 | 词库蒸馏完工仪式 |
| **短标签**（可选） | 内部备注，可有可无 | 不得进批量写稿主路径 |

废弃口头混用：创建页的「核心业务意图词库」易误解为 SEO 短词表；对外文案改为 **选题长问**（或「监测/写作问句」）。

前序归档里「关键词 = 要抢的问法」**收窄为：只要长问**；短词不再算正式「要抢的问法」。

---

## B. 正确作业顺序（入口契约）

```
创建（身份 + 一句话业务）
  → 阶段零出少量真人长问（Cursor 优先；模板仅保底）
  → 反重力豆包实战落盘
  → 确认回填：竞品候选 + 本题单长问
  → （可选）晋升为选题清单第一波 → 客户确认门闩
  → 再写首批文章 / 体检建站等
  → 沟通与复测中慢慢加长问
```

硬规则：

1. 创建默认 **选题空、竞品空**；若沟通时客户已口述问句/对标竞品，**允许**写入作为初始版本（仍可选、不强制）。  
2. 禁止「先蒸馏 50+ 短词再探活」；禁止创建页**自动出题**灌库。  
3. 探活问句经确认后，**可以且应当**成为第一波选题种子（可与创建时客户口述合并）。  
4. 清单完善靠沟通与监测，不靠一次机器灌满。

---

## C. 长问合格线（进清单 / 进写稿 / **探活出题**）

必须同时满足：

1. **像人说的**：完整句子；建议 ≥15 字；有场景、角色或「我想…」更佳。  
2. **答完能决策**：找谁 / 靠不靠谱 / 怎么选 / 有什么坑——不是名词解释条。  
3. **母盘盖得住**：我们有证据能答；答不了的先放「待补证据」，不进本周写稿队列。

**探活出题额外硬规则（「高质量必测题」提示词强制）：**

1. **维度可以留，措辞必须有人味**。禁止 SEO 时代关键词串（硬拼「城市+行业+哪家好」且无场景）。  
2. **先聊后盘**：IDE 必须在对话框里先列出拟问清单（编号 + 问句 + 为何问），供人改；**讨论定稿后再写入** `probe_script_*.json`（人明确说「直接落盘」才可一步写完，回复里仍须完整列题）。  
3. **必须并入创建时「客户期望完善的问题库」**：读 `project.yaml` 的 `keywords`；合格长问优先进题单；短渣过滤并在对话说明丢掉了哪几条。  
4. **竞品**：真对手 = AI 回答里会并列提及的名字；首轮题干不点名竞品；复测可用对比口吻但仍要像人说话。朋友 SOP 的榜单检索式、geoScore 表留给诊断报告，**不要**当豆包探活 query。

不合格：

- `徐州GEO`、`GEO优化`、行业两字短标签  
- 纯堆品牌名无问句  
- 「城市+行业+哪家好」模板味——**探活也不再默认采用**，须改成带角色/场景的真人说法后再问、再晋升

## D. 创建页改动

| 字段 | 处理 |
| :--- | :--- |
| 品牌/公司/一句话业务/地域/官网或托管 | **保留，创建主路径** |
| 「客户期望完善的问题库」 | **保留为可见可选填空**（不折叠、不强制）；沟通时客户说了「会搜什么 / 希望 AI 答好什么」就填，当作初始选题；没说就空 |
| 「已知竞品」 | **保留为可见可选填空**；客户点名要对标谁就填；没说清楚就空，探活后再从回答勾选回填 |
| 「生成必测题草稿」按钮 | **创建页永久删除**（不出题、不灌库）；出题只在阶段零 |

硬边界：删的是**自动出题**，不是这两个可选框。空着是默认；客户口述有料时允许直接落初始版本。

行业短标签：仅列表筛选用，**不是选题**。

## E. 阶段零改动

1. 页头：先问豆包几句真人会问的话；确认后可当第一波选题。  
2. **出题（任意 IDE）**：管理台「复制高质量出题提示词」必须要求——读 `project.yaml`（含客户期望问题库）+ 旧 probe；**对话框先列题供人改**；问句遵守 §C；再落盘 JSON。模板 `probe-script` 仅断网保底，并提示改成真人长问。  
3. 回填预览：竞品候选 vs 本题长问；可勾选「写入选题清单」。  
4. 回填只收合格长问；短渣过滤。

探活**维度**保留，**说法**必须口语化：

- 品类选型 / 品牌认知 / URL·人物锚点 / 价格与坑 /（可选）场景与对比

## E2. 与「朋友·竞品分析 SOP」的边界

| 采用 | 不采用（本轮） |
| :--- | :--- |
| 真对手 = AI 里抢同一推荐位；禁止瞎编 | 把 `{品类} 排名 2026` 等检索式直接当探活题 |
| ≤5、同赛道；探活后回填 | 创建时灌满竞品评分表 |
| 对比类口吻可作复测长问素材 | 本轮不做完整 geoScore→可见度折算引擎 |

## F. 选题清单页（原关键词页）

- 标题/说明改为：**选题长问清单**（可副标题保留「原关键词」一季过渡）。  
- 列表只展示长问；客户确认门闩确认的是长问。  
- 发帖运维门闩：未确认长问则黄条提醒（行为可与现门闩一致）。  
- 「意图矩阵 / 裂变」：生成结果经 §C 过滤后才能「加入清单」；默认不自动灌短词。

---

## G. 数据模型（`project.yaml`）

短期兼容（少迁库）：

- 继续用 `keywords: []` 存**选题长问**（语义变更，字段名可暂不改）。  
- `competitors: []` 仍由探活回填。  
- `keywords_confirmed*` 门闩语义改为「长问已与客户确认」。  

可选增强（tasks 里单列，可二期）：

- `topic_queries` 显式长问列表；`keywords` 废弃或只读迁移  
- 每条选题元数据：`source: probe|client|manual|evolve`、`promoted_from_probe: true`

存量短词：不自动删除；写稿/确认 UI **跳过不合格项**并提示「请改成或替换为长问」。

## H. 接口与前端要点

| 能力 | 说明 |
| :--- | :--- |
| 创建 API | 允许空 `keywords` / 空 `competitors`（已支持则保持；去掉引导灌词） |
| `POST .../probe/apply` | 回填时过滤短词；增加「晋升选题」开关（body 或勾选） |
| 意图/裂变 apply | 服务端按 §C 过滤；返回 `rejected_short[]` |
| 管理台创建弹窗 / 阶段零 / 选题页 | 文案与按钮按 §D §E §F |
