# Proposal: 创建与阶段零先探活再长问选题

## Why (为什么做)

当前入口逻辑让人「还没问豆包，就要填意图词库/竞品」，随后又用短词蒸馏灌出「徐州GEO」一类渣词当写作对象——和 GEO 真实作业（真人长问 → 探活 → 慢慢加选题 → 再写文）相反。

已定方向（本轮探讨共识）：

1. **清单只留长问**（真人会说的完整问句）；短词不当选题、不当文章标题。
2. **词库慢慢完善**：跟客户沟通 / 探活 / 监测一点点加，禁止「第一次蒸馏一大表当完工」。
3. **阶段零探活 = 基线体检**：弄清 AI 认不认识你、推谁、有没有幻觉；探活用的长问可晋升为**第一波选题**。
4. **创建时不应填**「核心意图词库 / 竞品」——那时根本填不准；创建只收身份与一句话业务。

前序归档：`openspec/changes/archive/2026-09-16-对照苍何诊断与答题卡母盘的交付提升探讨/`（母盘/文章/首次两篇等仍有效；本变更修正「关键词从哪来」）。

## What Changes (改动了什么)

1. **创建客户页**：弱化/挪走「核心业务意图词库」「主要竞品」；禁止在创建时一键灌短词；必填收缩为品牌/一句话业务/地域等身份字段。
2. **阶段零文案与流程**：明确探活产出 = 基线长问 + 竞品候选；出题以真人长问为准；模板短句仅保底且不得直接进写作队列。
3. **选题清单语义**：原「关键词清单」改为以**长问选题**为主；客户确认对象 = 长问；短词若保留仅作可选备注/内部标签，默认不展示、不进批量写稿。
4. **蒸馏/意图/裂变**：出口加过滤器——不合格短词不得写入 `keywords` 写作真源；合格标准写入本 design。
5. **晋升路径**：探活题单经人工确认后，可一键/半自动晋升为选题清单第一波（可编辑后再确认）。

## Capabilities (新增或修改的对外能力)

- 创建：空选题、空竞品为默认正确路径。
- 阶段零：探活 → 预览 → 确认回填竞品与长问；可选「晋升为选题清单」。
- 日常运维选题页：只展示/确认长问；门闩仍表示「客户已确认这些长问」。
- 批量生成草稿：只允许绑定已确认长问；禁止用短词当标题种子。

## Impact (受影响的部分)

- 前端：`web/index.html`（创建弹窗、阶段零、关键词/选题页文案与交互）
- 后端：`tools/geo/probe_backfill.py`、`intent.py` / evolution 写入路径、`utils.update_project_profile`、相关 API
- 规范引用：`docs/sop/delivery-sop.md`、阶段零相关 SOP；**规范真源只在本 OpenSpec**，不新建 `docs/specs` 旁路
- 存量项目：已有短词清单不强制清空；新逻辑下「确认/写稿」只认长问，短词迁移策略见 design

## 非目标（本轮不做）

- 不重做 01～05 全流水线业务
- 不改为双站
- 不在本轮实现完整「词×文×链」台账（仍挂 roadmap 欠账 A）
