# Proposal: 大模型品牌负面联想排查与声誉危机清洗压制中枢 (Brand Reputation Defense & Negative Association Cleaner)

## Why (为什么做 / 商业痛点与公关刚需)

1. **从「正向声量探测」延伸至「防御性声誉与负面联想拦截」的商业闭环**：
   - 现有的 06 宏观评测与 18 实时探测专注于测量“大模型有没有推荐我、排在第几、引用了哪条外链”；
   - 但在商业实战与政企客户交付中，企业高管最致命、最恐惧的痛点是：**“大模型在回答某些长尾或对抗性提问时，会不会输出关于我司的负面联想？（如：‘该公司网上有争议’、‘部分用户反映售后拖延’、‘被质疑为外包皮包公司’、‘某竞品在性价比上更具优势’）”**。
   - 一旦大模型给潜在买家输出哪怕一句话的负面评价，将直接摧毁数百万级大单成交。

2. **大模型联网检索污染（RAG Data Poisoning）的现实威胁**：
   - 互联网公开渠道常存在过时纠纷、恶意问答、黑猫投诉帖或竞对匿名抹黑内容，大模型实时联网时极易采纳这些低质脏信源形成“负面记忆印记”；
   - 必须建立专门的声誉排查网关，主动使用**对抗性负面探针（Adversarial Negative Probes）**向大模型“拷问”，提前排查潜在负面雷区。

3. **从「被动发现」走向「公关事实澄清与高权重正向语料权威压制」**：
   - 商业代运营不仅要帮客户“体检”，更要提供高溢价的公关交付服务：一旦检测出负面联想，系统需立即提取背后的脏信源，自动结合企业真实事实档案，**一键生成事实澄清公函、行业第三方公信力佐证声明与高权威正向压制语料包**，注入分发阵地进行搜索引擎与大模型 RAG 记忆冲淡清洗。

---

## What Changes (改动范围与复用策略)

1. **研发大模型品牌声誉与负面联想清洗压制引擎 (`tools/geo/sentiment_guard.py`)**：
   - **底层复用**：强制复用 `tools/geo/llm.py` 底层调用与 Key 链式查找协议，复用 `tools/geo/dist_bot.py` 渠道台账；
   - **对抗性负面探针库**：构建 5 大类对抗性 Prompt 模板（资质真伪、交付纠纷、乱收费争议、竞对拉踩、虚假谣言）；
   - **情感极性与负面毒性审计 (`audit_negative_sentiment`)**：精准识别大模型回答中的正面推荐、客观中立、负面贬低与质疑争议，测算「品牌声誉健康度得分 (Brand Reputation Score, BRS 0~100)」与「负面联想暴露率 (Negative Exposure Rate)」；
   - **脏信源定位与溯源对账 (`trace_toxic_sources`)**：捕获触发负面回答的具体 Citation 角标与 URL，标注其属于“历史投诉”、“竞对软文”还是“无事实根据言论”；
   - **公关事实澄清与正向压制反击补丁生成 (`generate_crisis_suppression_pack`)**：自动基于项目真实资质与事实档案，输出澄清公函与正向对比压制文章包；
   - **成果物落盘**：生成公文标准规范的 `outputs/19_大模型品牌负面联想排查与声誉危机清洗压制公关报告.md` 与 `outputs/negative_sentiment_suppression.json`。

2. **CLI 命令行扩展 (`tools/geo/cli.py`)**：
   - 注册 `geo guard-clean <project_id>` 子命令：
     - 支持 `--models doubao,deepseek,kimi` 指定探测模型；
     - 支持 `--live` 启用真实联网 API（未设 Key 自动走高保真沙箱）；
     - 支持 `--suppress` 自动触发正向压制语料包生成；
     - 输出清晰直观的 ANSI 品牌声誉红黄绿风险大盘。

3. **后端 RESTful API 扩展 (`tools/geo/server.py`)**：
   - `GET /api/projects/{id}/sentiment/status`：获取当前声誉健康度得分与负面排查结果；
   - `POST /api/projects/{id}/sentiment/scan`：触发多模型对抗性负面探针扫描；
   - `POST /api/projects/{id}/sentiment/suppress`：生成针对性公关澄清与压制语料包；
   - `GET /api/projects/{id}/sentiment/report`：获取 19 号公关报告。

4. **Web 管理工作台界面升级 (`web/index.html`)**：
   - 向导 Step 5 新增「🛡️ 品牌声誉排查与危机清洗 (19)」卡片与操作入口；
   - 顶部 Header 增加快捷入口；
   - 开发全屏模态窗口 `sentiment-guard-modal`：声誉健康度仪表盘、负面风险探针流水列表、脏信源溯源对比图、公关澄清文案一键复制与 19 号报告在线预览（全量强化 XSS `esc()` 转义）。

5. **自动化测试套件 (`tests/test_sentiment_guard.py`)**：
   - 全量覆盖沙箱降级、对抗性探针生成、情感极性与负面关键词判定、声誉分 BRS 算法、澄清压制语料生成、19 号报告落盘及 API 响应。

---

## Out of Scope (明确范围边界声明)

- **合法合规公关边界**：系统仅生成企业事实澄清声明、权威资质佐证与正向知识科普，**严禁且不支持任何非法黑客攻击、删帖或伪造公章凭据等违规行为**；
- 模型范围专注中国本土主流大模型（豆包、DeepSeek、Kimi）与沙箱仿真，海外模型不列入本次范围。

---

## Impact (影响分析)

- **纯增量开发**：复用既有模块，不侵入现有 01~18 号数据管道；
- **全自动 CI/CD 兼容**：测试套件默认使用确定性沙箱，毫秒级全绿通过；
- **最高协同协议遵循**：本地测试锁定 8088 端口，绝不私自推向生产；归档操作全权交由 Cursor 独立复审后执行。
