#### 对照 DeepGEO「诊断」定义（About §四 交付阶段表）
DeepGEO 诊断要求：用**品牌词 / 品类词 / 场景词 / 竞品词**测多个 AI 入口，记录 **是否被提及、是否被说对、引用来自哪里**，并归因到 **实体定义 / 内容缺口 / 技术访问 / 外部信号 / 竞品占位**。

| DeepGEO 诊断要件 | 本变更 Step 1 规范/产出 | 判定 |
| :--- | :--- | :---: |
| 多 AI 入口实测（豆包/DeepSeek 等） | design 写「推演」；01 报告为同质化模拟表，无真实 API/联网探针留证 | 🔴 |
| 品牌是否被提及 | 有关键词提及位次列，但全表复制粘贴同一结论 | 🟡 |
| 是否被说对（答案准确度） | 规范与 01 报告均未要求/未记录 | 🔴 |
| 引用来自哪里 | 未做 Citation/信源溯源 | 🔴 |
| 五类根因归因 | 偏技术底座扣分（SSR/llms/Schema），缺实体/内容/外部信号/竞品结构化归因 | 🔴 |
| 真实问法与购买决策链路（About §三） | keywords 有徐州本地词，但无 L1/L2/L3 问法分层与决策链拆解 | 🟡 |
| FAQ Q4 第一阶段：现状分析 + 问法研究 + 知识体系规划 | Step 1 只覆盖「体检+推演」，「定义/知识体系规划」被拆到后续或缺失 | 🟡 |

#### 与 DeepGEO 对齐得好的部分（可保留）
1. **先诊断后建设**与 DeepGEO「诊断 → 定义 → 建设 → 监测」顺序一致，Step 1 作为流水线入口正确。
2. 技术侧补齐 `/llms.txt`、`/sitemap.xml`、`/robots.txt` 的对标逻辑成立：实测 `deep-geo.cn` 上述三路径均为 **HTTP 404**，About 页却强调技术 GEO / Schema / 抓取链路——工程短板指控有效。
3. 徐州制造业 / 高客单价 B2B 定位与 About §五「工业制造、企业服务」适配客户画像一致。

#### 🔴 违规 / 必须修正（针对 Step 1）
1. **诊断验收标准缺失**：`proposal.md` / `design.md` / `tasks.md` 的 Step 1 未写入 DeepGEO 级硬验收：多模型实测留证、提及/说对/引用三栏、五类根因结论。
2. **01 报告不可作为谈单样板**：竞品写成笼统标签（「一线城市高溢价…」），非具名竞品；全表同一句「采纳原因」；站点 HTTP 0 时仍给技术扣分叙事，说服力不足。
3. **承诺口径冲突**：proposal 写「100% 垄断性首选推荐」，与 DeepGEO About Q8「不会承诺 AI 一定推荐」直接相悖——售前话术风险，Step 1 报告亦不得沿用绝对承诺。

#### 🟡 架构/方法风险
1. 框架三套并存易混淆：DeepGEO 四阶段（诊断/定义/建设/监测）≠ 本变更五步（audit…monitor）≠ design 首页「锚定/监测/洞察/塑造」。Step 1 应对齐「诊断」，并在 design 标明映射关系。
2. DeepGEO「定义」阶段（统一品牌/服务/边界标准表达）在本变更 Step 1 之后直接进 scaffold，**实体口径统一**落点不清，易导致后续 rewrite 口径漂移。

#### 🟢 优化建议（Step 1 补强清单）
1. 在 `design.md` Step 1 增加验收表：≥N 组品牌/品类/场景/竞品词 × ≥2 模型；每条记录「提及 / 说对 / 引用源 / 根因」。
2. `project.yaml` competitors 改为 2+ 具名竞品（可含 deep-geo.cn 作为方法对标，另选本地/行业替代声量对象）。
3. 01 报告结构改为 DeepGEO 诊断四问：AI 知不知道你 → 说没说对 → 引用何处 → 缺口在哪类。
4. proposal 删除或改写「100% 垄断」类绝对承诺，改为可监测指标（提及率、引用质量、答案准确度基线）。

#### 结论一句话
**Step 1「先做 audit」这个方向可以做；按 deep-geo.cn/about 的诊断标准，当前规范与 01 产出深度不够，需修正后再视为合格第一步。**
