# Proposal: 多版本生成采纳与草稿废纸篓安全回档

## Why (为什么做)
- **痛点一（无法区分新旧生成）**：交付人员在点击“重新抓取底座”或“重新出具初稿”后，由于文件名固定且缺乏清晰的生成时间戳与版本号，肉眼无法直观确认当前文件是刚刚重生成的新数据，还是上一版的旧数据，造成严重的不确定感。
- **痛点二（废弃草稿越积越多）**：在阶段一到阶段六的完整交付中，反复出稿、试算可能衍生多份无用草稿或历史版本。如果不允许删除，左侧资源管理器文件臃肿杂乱；但若允许全盘随意物理删除，一旦误删了流水线依赖的核心骨干文件（如底座指标、母盘、主报告），右侧 SOP 动线和下游交付会直接断链报错。
- **业务价值**：引入一套兼顾“新旧版本直观感知”、“废弃草稿安全删除”与“生效底牌强制保护”的闭环机制，让交付专家既能随时清除无用草稿、随时反悔回档，又能确保核心交付物稳固如山。

## What Changes (改动了什么)
1. **统一交付物版本采纳模型**：沿用阶段零验证成功的模式，流水线中的文件分为两类状态：
   - **已采纳（客户生效版本）**：当前流水线生效的主文件，带有系统专属绿色徽章（如 `客户生效版本 [V1]`），受系统安全保护，**禁止删除**；
   - **草稿（未采纳版本）**：重新抓取/生成时派生出的新版本或候选版本，带有中性灰 `[草稿]` 徽章，允许交付人员随时删除。
2. **多版本生成与一键采纳（工序槽位互斥）**：
   - 重新生成或重新抓取时，支持生成带时间戳与版本号的新版本；
   - 中栏顶部操作区提供【设为客户采纳】按钮，点击后新版本获得已采纳标记，同工序槽位（同一交付物主干）的旧版本自动退回为普通草稿，绝不波及同分类下的其他独立交付物。
3. **安全软删除与废纸篓收纳**：
   - 草稿文件卡片 hover 时展示轻量删除垃圾桶图标，点击标记 `is_deleted: true`，从主列表中隐藏；
   - 资源管理器底部新增【已归档 / 废纸篓】折叠抽屉，汇总展示所有被删草稿；
   - 废纸篓内每个文件均提供【恢复】按钮，点击即可一键原位回档，零数据丢失风险。
4. **生成时间戳与版本感知**：
   - 中栏底部状态栏清晰展示文件的生成时间（如 `生成时间: 2026-09-28 20:01:25`）与版本标识（`V1`），彻底消除“到底有没有更新”的焦虑。

## Capabilities (对外能力)
- **交付物版本采纳引擎（Artifact Adoption Engine）**：支持一键将候选草稿升格为客户生效版本，并在同工序槽位内安全替换旧版本。
- **阶段内废纸篓与即时回档（Stage Trash & Instant Rollback）**：阶段内部提供轻量安全的软删除与一键恢复抽屉，无需跳转全局复杂回收站。
- **生成时间戳与版本可视化（Timestamp & Version Badge）**：生成时间戳与版本标签清晰透出，让每一次重新生成都有迹可循。

## Impact (受影响的部分)
- `GEO/web/step0-src/components/studio/StudioFileTree.vue`：
  - 资源管理器文件树升级：支持通用展示 `已采纳` / `草稿` 徽章；
  - 草稿文件支持删除按钮，派发 `deleteFile` 事件；
  - 底部新增【已归档 / 废纸篓】折叠展开与【恢复】按钮，派发 `restoreFile` 事件；
- `GEO/web/step0-src/stage1Config.js`：
  - 阶段一初始文件注入 `isActive: true`、`versionTag: 'V1'` 与初始生成时间戳；
- `GEO/web/step0-src/useStep1.js`：
  - 增加 `handleAdoptFile` 采纳方法；
  - 增加 `handleDeleteFile` 软删除与 `handleRestoreFile` 恢复方法；
  - 重新抓取时生成带版本和生成时间戳的最新指标，自动持久化至本地；
- `GEO/web/step0-src/Step1App.vue`：
  - 胶水层连接 `StudioFileTree` 的 `delete-file` 与 `restore-file` 事件，连接 `<StudioEditor>` 的 `adopt-file` 采纳事件；
  - 为 `<StudioFileTree>` 显式绑定 `:show-status-badge="true"`，在阶段一开启采纳状态与废纸篓能力；
- `GEO/web/step0-src/Step0App.vue`：
  - 阶段零补齐胶水层连接：实现 `handleDeleteFile` 与 `handleRestoreFile`，绑定 `<StudioFileTree>` 的 `delete-file` 与 `restore-file` 事件，实现全阶段草稿删除与废纸篓回档闭环；
- `GEO/web/step0-src/components/studio/StudioEditor.vue`：
  - 放宽 `canAdoptCurrentFile` 判定守卫（支持阶段一的 materials/drafts/reports 分类或带 versionTag 的文件），点击派发 `adoptFile` 事件；
  - 顶部与底部状态栏透出文件生成时间戳与版本号。
