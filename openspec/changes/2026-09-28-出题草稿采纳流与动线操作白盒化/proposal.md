# Proposal: 出题草稿采纳流与动线操作白盒化

## Why (为什么做)
1. **重新出题与版本生成机制黑盒**：
   - 交付专家点击“重新出题”后生成了第 2 版题目，但左侧资源管理器第一版显示 `[已采纳 QA-V1]`（因宽度截断常被误读为 `QAVE`），第二版显示为裸文本名 `01_豆包题目_第2版.txt`；
   - 交付专家困惑：QA-V2 版本号是怎么产生的？如果我想以第 2 版深入完善并保存，该怎么做？系统没有直观的视觉反馈和流程引导。
2. **动线第 3 步“保存文件并采纳”操作割裂**：
   - 目前右侧动线第 3 步仅有静态文字“在中间工具栏点击【保存文件】并点击【设为客户采纳】”，缺乏可点击的实体动作按钮；
   - 用户产生困惑：“我保存了什么文件？保存在哪里？为什么左边文件树没有新文件？”（实际上保存的是当前文件本身，并非另存为，但界面未做透传解释）。
3. **左侧文件树视觉挤压与状态缺失**：
   - 资源管理器宽度过窄（仅 240px），导致文件名被严重截断为 `01_豆...`，药丸标签被挤压变形；
   - 未采纳的草稿文件没有任何状态标签，无法直观区分哪些是“草稿”，哪个是“当前生效底牌”。
4. **平铺动线卡片误点击引发跨页跳转与报错隐患**：
   - 平铺模式下卡片头部依然监听 `@click="onGotoStep(idx + 1)"` 并分发 `switch-step`，用户误点卡片 2 会直接跳到 0.2 页面；若点击卡片 3，则会派发 `switch-step(3)`，由于 `subMetaMap[3]` 不存在还会引发未捕获异常。

## What Changes (核心改动)
1. **右侧三级动线操作白盒化（动作按钮直接挂载进卡片）**：
   - **微步骤 1（AI 出题与查看）**：展示出题说明，保留实体按钮【重新出题（生成新版）】；
   - **微步骤 2（中间区润色打磨）**：清晰说明“在中间编辑器直接润色”，提供实体按钮【保存当前润色修改】（直连 `handleSaveActiveFile`），明确提示“已保存对当前文件的修改”；
   - **微步骤 3（采纳生效生成新版本）**：提供实体按钮【采纳为生效底牌】（直连 `handleAdoptFile`），点击后将当前草稿立即转正为 QA-V2，文件头盖上生效印章，自动配对 0.2 实测文件；
   - **保持 0.2 动线独立稳定**：0.2 网页提问动线 `STAGE0_SUB2_META` 及其第 3 步的【完成阶段零并封版】按钮保持现状，不受任何影响。
2. **左侧资源管理器视觉与状态透传升级（防御跨阶段共用污染）**：
   - **四阶段统一宽度拓宽**：将四阶段共用的 `StudioFileTree.vue` 侧栏宽度由 `w-60`（240px）统一拓宽至 `lg:w-72`（288px），保障所有阶段的长文件名清晰可读；
   - **状态徽章精准作用于阶段零**：给 `StudioFileTree.vue` 增加可选 prop `showStatusBadge: { type: Boolean, default: false }`，仅在 `Step0App.vue` 传入 `:show-status-badge="true"`；
   - **状态白盒化与统一紫系配色**：在开启状态徽章时，草稿文件显式标灰 `[草稿]`（`bg-slate-100 text-slate-400 border border-slate-200`）；生效底牌显式标高亮紫 `[已采纳 QA-V(N)]`（`bg-[#7c5bf5]/15 text-[#7c5bf5] border border-[#7c5bf5]/30`），阶段 1/2/3 默认保持 `false` 不受任何污染。
3. **彻底阻断平铺模式下的误触跳页**：
   - 在 `StudioSop.vue` 中，当 `expandAll === true` 时，卡片头部点击仅做视觉聚焦或无操作，严禁向外派发 `switch-step` 跨页事件，彻底消除跳页及数组越界隐患。

## Capabilities (对外能力)
- 交付专家在阶段零出题与打磨时，流程完全白盒：出题 -> 编辑并点保存 -> 采纳转正（生成 QA-V2），每一步都有直接的实体按钮与状态回馈；
- 资源管理器状态清清楚楚（哪个是生效底牌、哪些是打磨中的草稿），且绝不破坏阶段 1/2/3 的文件展示；
- 彻底杜绝动线卡片误点击导致跳页与崩溃的混乱交互。

## Impact (影响范围)
- 前端源码：
  - `GEO/web/step0-src/components/studio/StudioSop.vue`（卡片防误触，动作分发，清理悬空事件）
  - `GEO/web/step0-src/components/studio/StudioFileTree.vue`（宽度拓宽至 `lg:w-72`，新增 `showStatusBadge` prop 与紫系二元徽章）
  - `GEO/web/step0-src/Step0App.vue`（升级 `STAGE0_SUB1_META` 动作配置，绑定保存与采纳事件，传 `:show-status-badge="true"`）
- 前端构建产物：在仓库根目录 `GEO/` 执行 `npm run build:step0`，生成 `web/assets/step0/step0.js` + `geo-step0-island.css` 并同步至 NE1 8088 运行环境。
